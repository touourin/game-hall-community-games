# 卡牌与场景建模说明

## 1. 模型分层

本目录把规则身份、运行时状态和视觉表现分开：

1. `model/component-catalog.json` 是货物、骰子、投入成本、收益、贷款和航线阈值的规则常量；
2. `model/card-model.json` 定义份额卡的几何、语义区域、隐私状态和原创材质；
3. `model/card-catalog.json` 固化 20 张唯一份额卡实例；
4. `model/game-state.schema.json` 描述服务端完整真值；
5. `model/view-state.schema.json` 描述隐私安全的玩家/公共快照；
6. `model/state-machine.json` 定义阶段、动作与自动事件；
7. `model/scene-catalog.json` 把状态阶段映射为可测试的前端场景。

规则引擎只读模型中的语义字段，不从颜色、SVG 坐标或中文文案推断成本与收益。

## 2. 份额卡

### 2.1 实例与身份

四种货物各有 5 张份额：

| 货物 | 实例 ID 范围 | 语义色 | 辅助纹样 |
| --- | --- | --- | --- |
| 人参 | `share-ginseng-01..05` | 赭黄 | 斜向根纹 |
| 肉豆蔻 | `share-nutmeg-01..05` | 铜棕 | 点状籽纹 |
| 丝绸 | `share-silk-01..05` | 靛蓝 | 横向织纹 |
| 玉石 | `share-jade-01..05` | 青绿 | 菱形切面 |

颜色不是唯一编码。牌面同时显示中文名、英文短名、两字母代码和不同纹样，读屏名称格式为“{货物}份额，第 {序号} 张”。

### 2.2 几何

- 逻辑尺寸：72 x 104；
- 圆角：8；
- 安全内边距：7；
- 顶部身份区：代码和“货物份额”；
- 中央主视觉区：中文名与抽象图形；
- 底部状态区：市场价值由 UI 叠加，不印成静态规则值；
- 最小点击目标：44 x 44 CSS px；
- 手牌在窄屏使用局部横向滚动，不缩到文字不可辨。

### 2.3 正面、背面与抵押

| 状态 | 本人看到 | 其他玩家看到 | 规则含义 |
| --- | --- | --- | --- |
| 未抵押 | 正面、货物、当前价值 | 中性统一牌背/数量 | 终局计价值，可抵押换 12 |
| 已抵押 | 正面加“已抵押 12 / 赎回 15”带 | 中性统一牌背加抵押计数 | 仍计终局货物价值，再扣 15 |
| 市场供应 | 按货物公开的通用正面 | 同样公开 | 港务长可按当前价购买 |

牌背不能带货物色或细微变体，避免通过像素差异识别私密份额。抵押状态的具体货物也不能进入对手 DOM、CSS 类名、日志或无障碍文本。

### 2.4 生成物

`scripts/generate_assets.py` 从卡牌与组件模型生成：

- `model/card-catalog.json`；
- `assets/share-card-sheet.svg`；
- `assets/table-scene-blueprint.svg`。

生成物带 `data-model-version="1.0.0"`，校验器会检查数量、ID、货物分布和 XML 完整性。修改源模型后应重新运行生成器，不直接手改生成文件。

## 3. 非卡牌组件

### 3.1 货船

三艘 `punt-1..3` 是中性的容器，货物身份每航行重新绑定。船上槽位来自当前货物：

- 人参、肉豆蔻、丝绸：3 位；
- 玉石：4 位。

槽位 UI 显示“成本 n”，但点击后客户端只提交目标船；服务端根据当前最低空槽查成本。海盗第二轮登船也占用同一槽位。

### 3.2 航线

三条航线固定为 `lane-1..3`，每条显示 0-13。稳定快照必须满足：

- 每艘航行船恰占一条不同航线；
- 起始位置在 0-5 且总和为 9；
- 坐标只存 0-13，越过 13 后立即转换为 port 状态；
- 13 使用独立高对比描边和海盗图标，不只靠红色；
- 船只移动动画结束前，目标格和数值文本已经可读。

### 3.3 港口与船坞

两组区域都按 A/B/C 固定，不随当前占用重排：

- A：成本 4，收益 6；
- B：成本 3，收益 8；
- C：成本 2，收益 15。

每个槽位同时容纳一个投注助手和至多一艘结算船，二者是不同层。动画可以把船临时放在飞行层，但稳定状态必须回到相应槽位。

### 3.4 特殊岛

- 海盗船：船头/船尾两槽，必须显示当前船长；
- 小引航员：成本 2、影响总量 1；
- 大引航员：成本 5、影响总量最多 2；
- 保险：显示已领取 10 和潜在 A/B/C 最大责任。

特殊位置的工具提示应同时写“成本、何时行动、是否直接收益”，不能只显示风格化图标。

## 4. 场景目录

前端使用以下稳定 `sceneId`：

| 场景 | 阶段 | 主焦点 |
| --- | --- | --- |
| `setup.table` | setup | 玩家席、规则摘要、空航线 |
| `auction.bid` | auction | 当前价、领跑者、可支付能力、Pass |
| `harbor.share` | harbor_share | 四种份额供应与实际购买价 |
| `harbor.load` | harbor_load | 四选三并绑定三艘船 |
| `harbor.launch` | harbor_launch | 三条航线和起点总和 9 |
| `placement.choose` | placement | 全部合法空位、成本和剩余助手 |
| `movement.roll` | roll | 港务长掷骰、其他玩家等待 |
| `movement.order` | move_order | 三枚骰点和港务长处理次序 |
| `pirates.board` | pirate_board | 13 格目标、空船位、船长先后 |
| `pilot.small` | pilot_small | 一艘船 +/-1 或 Pass |
| `pilot.large` | pilot_large | 一艘最多 2 或两艘各 1 |
| `pirates.route` | pirate_route | 被劫船、港口/船坞下一空位 |
| `voyage.summary` | voyage_summary | 收支账目、涨价、贷款与下一航行 |
| `game.finished` | finished | 财富公式、排名、共同赢家 |

场景只描述“此刻用户看什么、能做什么”。规则阶段仍由服务端状态机决定，不能让 Vue 组件自行跳到下一场景。

## 5. 牌桌构图

`assets/table-scene-blueprint.svg` 使用桌面 16:10 逻辑画布：

- 顶部 14%：玩家财务轨；
- 左侧 18%：黑市价值与份额供应；
- 中央 54%：三条航线和三艘船；
- 右侧 20%：港口与船坞；
- 航线周围：海盗、引航员和保险；
- 底部 18%：本人私密份额与主操作面板。

空间关系保持稳定。场景变化通过焦点框、状态标签和动作面板表达，不把港口、船坞或市场在不同阶段搬到新位置。

## 6. 响应式策略

### 宽屏（>= 1024px）

所有区域同屏，航线为横向主轴；本人份额抽屉固定底部。

### 平板（768-1023px）

市场缩为四列指标，港口/船坞仍在航线右侧；特殊岛改为航线下方四格。

### 手机（< 768px）

1. 顶部玩家轨局部横向滚动；
2. 中央航线区局部横向滚动并吸附 0、5、9、13；
3. 港口/船坞作为航线尾部的一部分，不拆成看不见的弹窗；
4. 本人份额和财务操作放在可展开底部抽屉；
5. 当前动作使用固定底部栏，但不遮挡被选目标；
6. 页面根元素 `min-width: 0; max-width: 100%`，禁止页面级横向溢出。

## 7. 动画模型

推荐事件：

| 事件 | 表现 | 规则边界 |
| --- | --- | --- |
| `dice.rolled` | 三枚骰从对应货物区亮起 | 骰点已由服务端持久化 |
| `punt.moved` | 船沿固定航线平移 | 目标位置已在快照中 |
| `punt.docked` | 船进入 A/B/C 槽 | 槽位由服务端确定 |
| `pirate.boarded` | 助手从海盗船到货船空槽 | 不能由动画选择被登船船只 |
| `punt.plundered` | 船上助手淡出、收益飞向海盗 | 账目已结算 |
| `pilot.influenced` | +/-1 或 +/-2 路径高亮 | 不重算骰点 |
| `market.advanced` | 价值标记跳到下一离散格 | 使用服务器目标值 |
| `settlement.paid` | 逐条高亮账目 | 可跳过，不影响下一状态 |

事件 ID 单调递增。断线重连直接显示稳定快照，不追播旧动画。

## 8. 无障碍

- 每艘船的读屏文本包含货物、当前位置、距越过 13 所需最少步数和助手数量；
- 每个部署位包含区域、成本、成功收益与占用状态；
- 13 格、海盗候选和当前玩家使用图标、文字、描边三重编码；
- 卡牌货物通过名称、代码和纹样区分，不只靠颜色；
- 拖拽若实现，必须同时提供点击选择和键盘确认；
- 结果动画可跳过；`prefers-reduced-motion` 下位移改为短淡入；
- 私密抽屉打开时正确管理焦点，关闭后回到触发按钮；
- 规则层始终高于动画层，打开规则时底层不可点击。

## 9. 原创边界

蓝图只使用抽象货箱、航线、文字和几何纹样。它不是官方版图的描摹，也不是可直接印刷替代原作的 PnP 套件。正式 UI 可以延续本仓库的中性材质系统，但不得：

- 使用官方 Manila Logo；
- 从规则 PDF、开箱图或扫描件裁切图像；
- 临摹官方份额插画、版图建筑或包装构图；
- 用颜色或装饰暗示模型中不存在的额外规则。
