# 场景模型与交互规范

## 1. 场景目标

牌桌必须让玩家一眼看清三件事：本回合航道已经有哪些爆牌键、继续抽牌的风险、每位玩家各花色银行顶牌。视觉气氛可以有海图和船舱质感，但不能牺牲卡牌点数、效果选择和因果反馈。

`model/scene-catalog.json` 使用 1600×900 逻辑画布和 0–1 归一化区域。实现可用 CSS Grid/Flex，而不要求绝对像素；坐标用于视觉验收、动画起终点和原型生成。

## 2. 信息架构

宽屏从外到内分为：

1. 顶部状态栏：轮次、当前玩家、规则档案、抽牌剩余和变体。
2. 三侧对手银行：玩家名、公开特性、实时得分、十个花色堆摘要。
3. 中央主区：左侧弃牌、中央航道、右侧抽牌；航道下方显示海怪债务与已出现爆牌键。
4. 底部个人银行：十个完整花色堆，能直接作为抓钩候选。
5. 底部操作条：抽牌、收牌、效果说明与规则入口。
6. 浮层：特性选择、效果目标、终局分项；浮层不能遮住当前被选择的区域。

## 4. 2–4 人座位

视角玩家始终位于底部，其他玩家按服务器座次相对旋转：

- 2 人：唯一对手在顶部，左右侧空出给弃牌详情和事件带。
- 3 人：两名对手位于左上、右上，顶部中间保留状态栏。
- 4 人：对手分别位于左、上、右；侧边银行使用纵向紧凑布局。

旋转只影响显示位置，不改变服务端“左手边”座次。贼岛和回合方向必须使用权威 `seat` 计算，不能根据 DOM 方位推断。

## 5. 航道布局

基础规则按花色爆牌时，航道理论上最多十张成功入场牌；奇异之地按点数爆牌时，同样最多六个不同点数，但连锁与暂存动画可能需要额外空间。

- 宽屏卡宽 112–128 px，间距可在航道超过 7 张后负向压缩，但点数角标不得遮挡。
- 每张 entry 上方显示序号，底部显示来源小标：抽牌、自己的银行、对手银行或弃牌。
- 已受保护 entry 使用盾形标与文字“受保护”；不能只加绿色滤镜。
- 船锚保护范围用细线括号连接，而不是给整个航道涂色。
- 当前爆牌牌停在航道右侧半个卡位，先显示与哪张牌重复，再进入分流动画。

## 6. 银行布局

每个玩家银行固定为十个花色槽，空槽也保留图标，使玩家可以快速判断弯刀合法性。槽位显示：

- 花色图标和名称；
- 顶牌完整点数；
- 总牌数；
- 展开后按高到低查看全部公开牌；
- 当前基础分和特性修正。

抓钩、火炮、弯刀选择时，只高亮服务端给出的 option。实体档案中会导致爆牌的合法选项加“将爆牌”警示；数字安全档案不会收到该 option。

## 7. 稳定场景状态

| Scene | 关键画面 | 主操作 |
| --- | --- | --- |
| `trait_selection` | 两张本人候选，其他玩家只显示“选择中” | 选择特性／魔柜目标 |
| `turn_ready` | 航道与风险表完整，抽牌和收牌状态明确 | 抽牌／收牌 |
| `effect_choice` | 当前能力说明、来源连线、合法目标 | 选择一个 option |
| `forced_draw` | 海怪计数占据操作条，收牌锁定 | 继续抽牌 |
| `bust_resolution` | 重复依据与保护分流 | 无，表现状态 |
| `collect_resolution` | 航道飞入对应银行，组合奖励随后出现 | 无，表现状态 |
| `finished` | 逐花色分项、修正、同分依据 | 再来一局／查看规则 |

服务端只发送当前稳定状态和事件；`bust_resolution`、`collect_resolution` 是前端表现标签，不应成为等待客户端确认的权威 phase。

## 8. 效果选择

桌面直接选择优先于通用下拉框：

- 抓钩：点击本人银行高亮花色堆。
- 火炮／弯刀：先点击玩家区域，再点花色堆；若合法目标少，可一步完成。
- 藏宝图：在弃牌旁展开最多三张公开候选。
- 水晶球：在抽牌堆上方悬停一张公开预览，直到当前玩家完成下一决定。
- 美人鱼：航道中较早 entry 轻微抬起，点击重演。
- 掠夺者／魔柜：使用玩家头像选项，但仍显示文字“选择整局目标”或“本次奖励目标”。

每个 option 都要有键盘按钮等价物和完整 `aria-label`。Esc 不能取消强制效果，只能关闭非阻塞规则说明。

## 9. 事件与动画

事件使用单调递增 `eventSeq`，前端按序消费。推荐 cue：

| Cue | 时长上限 | 表现 |
| --- | ---: | --- |
| `card_drawn` | 240 ms | 统一牌背从抽牌堆移动并翻面 |
| `card_entered` | 180 ms | 卡牌落入航道，爆牌键指示更新 |
| `effect_targeted` | 300 ms | 来源到目标的细线和目标脉冲 |
| `card_transferred` | 360 ms | 银行／弃牌／航道之间移动 |
| `oracle_revealed` | 500 ms | 抽牌顶牌抬起公开 |
| `kraken_debt_changed` | 260 ms | 数量滚动并配合“仍需 N 张”文字 |
| `bust_detected` | 520 ms | 两个重复键相连，航道短震 |
| `protected_split` | 650 ms | 受保护牌与弃牌分别飞向目的地 |
| `key_chest_bonus` | 每张 120 ms，最多合并展示 | 钥匙与宝箱拼合，奖励批次入库 |
| `turn_changed` | 220 ms | 当前玩家光环平移 |
| `score_resolved` | 800 ms | 花色分项依次汇总 |

减少动态模式移除位移、翻转、震动和连续发牌，只保留 120 ms 淡入、描边和文字状态。任何关键规则结果都必须在动画之后仍以静态标签存在。

## 10. 响应式规则

### ≥ 1180 px

完整四边牌桌。中央航道占可用宽度 62%–72%，自己的银行显示完整卡堆，对手显示顶牌和数量。

### 760–1179 px

顶部对手保持，侧边对手移入顶部三列；个人银行仍为十槽但允许两行。事件带折叠为图标。

### ≤ 759 px

采用单列舞台：状态栏 → 对手摘要横向条 → 中央牌堆／航道 → 风险表 → 自己银行 5×2 → 固定操作条。航道可在自身容器滚动，页面根节点 `overflow-x: clip`。

### ≤ 390 px

隐藏卡面能力短句但保留点数、图标、花色名；效果详情进入底部 sheet。点击目标最小 44×44 CSS px。

## 11. 主题 token

建议原型色：

```json
{
  "table": "#173b3a",
  "tableEdge": "#6f4f32",
  "paper": "#efe2c4",
  "ink": "#1e2928",
  "brass": "#b28a4a",
  "danger": "#a4473d",
  "protected": "#4f7f78",
  "focus": "#f2c96d"
}
```

深浅主题保持卡牌结构、图标与状态语义一致，只调整桌面、纸张和阴影材质。不要把海盗主题扩展成遮挡信息的大面积绳索、金币或人物装饰。

## 12. 可访问性与本地化

- 所有花色同时显示中文名、图标和点数；不只靠颜色。
- 屏幕阅读器在新牌入场时播报“白露抽到火炮 6，能力等待选择”，爆牌时播报重复依据和最终去向。
- 焦点在快照更新后保持于逻辑对象；被移动或删除时回到效果标题，不跳到页面顶部。
- 中文默认使用系统无衬线字体，数字使用等宽数字特性；英文名只在详情中出现。
- 文案为未来繁体中文／英文保留 key，不在组件内硬编码完整规则段落。

## 13. 原型验收

- 2、3、4 人座位都能从同一安全视图稳定映射。
- 航道 10 张时点数和保护标记仍清晰，无页面级横向滚动。
- 抓钩、火炮、弯刀、藏宝图和美人鱼五种选择可以仅用键盘完成。
- 爆牌动画明确展示“哪两张重复”和“为什么部分牌被保护”。
- 海怪未清零时，收牌按钮既禁用又提供文字原因。
- 终局分项可以独立复算服务端总分。
