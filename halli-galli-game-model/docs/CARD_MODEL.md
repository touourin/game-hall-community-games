# 水果牌模型

## 1. 模型目标

卡牌模型同时服务于服务端牌张守恒、前端渲染、规则提示、测试夹具和原创原型资源。语义唯一来源是 `model/card-catalog.json`，SVG 不反向承载规则。

本包只覆盖经典水果基础版：一张牌只含一种水果，数量为 1-5。不得从 Extreme、Junior、Party 等版本混入动物、多水果牌或其他触发符号。

## 2. 水果类型

| `fruitId` | 中文 | 英文 | 原型色 | 非颜色识别符 | SVG 几何 |
| --- | --- | --- | --- | --- | --- |
| `banana` | 香蕉 | Banana | `#F3C94A` | 弯月 + 梗 | 两条弧形路径围成月牙 |
| `strawberry` | 草莓 | Strawberry | `#E9545B` | 心形果身 + 籽 | 圆顶锥形果身、叶冠和圆点 |
| `lime` | 青柠 | Lime | `#79B94B` | 圆片 + 分瓣 | 圆形、内圈与放射分隔 |
| `plum` | 李子 | Plum | `#7D5AA6` | 椭圆果身 + 叶 | 竖向椭圆、偏置高光和叶片 |

颜色不能成为规则字段。计数逻辑只使用 `fruitId` 与 `fruitCount`；高对比／色觉模式可替换颜色而不影响牌面身份。

## 3. 牌面与副本

唯一牌面由 `(fruitId, fruitCount)` 决定，共 4 × 5 = 20 种。每种水果使用相同副本函数：

| `fruitCount` | `copies` | 每种水果实例 ID 示例 |
| ---: | ---: | --- |
| 1 | 5 | `banana-1-01` 至 `banana-1-05` |
| 2 | 3 | `banana-2-01` 至 `banana-2-03` |
| 3 | 3 | `banana-3-01` 至 `banana-3-03` |
| 4 | 2 | `banana-4-01`、`banana-4-02` |
| 5 | 1 | `banana-5-01` |

每种水果 14 张，总牌数为 56。牌面 ID 使用 `face-{fruitId}-{fruitCount}`，实例 ID 使用 `{fruitId}-{fruitCount}-{copy:02d}`。实例 ID 在一局内稳定，永远不下发到实时客户端的抽牌区。

## 4. JSON 结构

`card-catalog.json` 顶层包含：

- `schemaVersion`、`modelVersion`、`gameId`；
- `sourceBasis`：事实来源链接；
- `cardPhysical`：56 × 87 mm 原型纵横比、圆角和安全区；
- `fruits`：四种水果的语义、文字和原创视觉 token；
- `copyDistribution`：数量到副本数的唯一映射；
- `faces`：20 种牌面，明确 `fruitId`、`fruitCount`、`copies`、布局模板和无障碍标签。

服务端加载时应冻结目录并生成实例索引：

```text
instanceId -> {
  faceId,
  fruitId,
  fruitCount,
  copyIndex
}
```

客户端只需收到公开顶牌的 `faceId`、`fruitId`、`fruitCount` 和文本标签。牌背不应编码水果、数量或实例。

## 5. 牌面布局

基准卡面为 168 × 261 逻辑像素，对应 56:87 比例：

- 外框圆角 13，内安全区距边 12；
- 左上放大号数量，中央图形与底边标签重复数量信息，避免小尺寸下角标侵入标签区；
- 中央水果区占卡面约 70%，图形按 `fruitCount` 使用预设排布；
- 底边显示中文水果短名和 `×N`，便于低视力与调试；
- 原型图集额外显示“此牌面共几张”，实际游戏卡面可不显示副本数；
- 牌背使用中性同心铃纹，不使用官方 Logo、字体或包装色块。

### 5.1 数量排布

| 数量 | 位置策略 |
| ---: | --- |
| 1 | 中央单体，最大尺寸 |
| 2 | 左上／右下对角 |
| 3 | 上二下一的三角形 |
| 4 | 2 × 2 网格 |
| 5 | 四角 + 中央 |

每个水果图形还带自身轮廓特征；在灰阶、去色和 72 px 高度下，玩家仍应能借助形状与数字识别。

## 6. 动画与交互数据

卡牌本身没有点击抢铃之外的牌效。渲染组件接收：

```ts
type FruitCardProps = {
  faceId: string | null
  faceUp: boolean
  isTop: boolean
  justRevealed: boolean
  compact: boolean
  ariaLabel: string
}
```

- `faceUp=false` 时不得通过 DOM 属性、CSS 类、资源 URL 或无障碍文本泄露牌面。
- `justRevealed` 只控制视觉提示；规则已在服务端提交。
- 非顶牌只渲染堆叠边缘和张数，不渲染被覆盖牌面。
- 水果牌不是铃按钮的替代命中区，避免误触。

## 7. 牌张守恒

每个权威状态必须满足：

```text
所有玩家 drawPile 实例集合
∪ 所有玩家 discardPile 实例集合
= 目录生成的 56 个实例集合
```

集合两两不相交。正确铃只是跨玩家移动，误按只是抽牌堆之间移动，翻牌只是同一玩家从抽牌堆到明牌堆移动，因此任何动作前后总数都不变。

## 8. 原创资源边界

`assets/card-atlas.svg` 是 20 种唯一牌面的功能原型，不是复制件：

- 不使用 AMIGO／代理商 Logo、包装构图、字体或官方插图；
- 水果由代码生成的基础几何组成；
- 名称和数量属于规则信息；
- 发布级美术必须重新确认授权，并保持 JSON 中的语义 ID 不变。

## 9. 验收清单

- 四种水果、20 种唯一牌面、56 个实例总数正确。
- 每种水果的副本分布严格为 `5/3/3/2/1`。
- 所有 face ID、实例 ID 可逆解析且唯一。
- 1-5 的视觉图形数量与数字一致。
- 牌背完全中性；安全视图不泄露抽牌牌面。
- 色盲模拟、灰阶和 72 px 缩略图仍能依靠轮廓与数字辨认。
- SVG 可由脚本确定性重建并通过 XML 解析。
