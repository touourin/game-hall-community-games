# 场景模型

## 场景边界

`model/scene-catalog.json` 将完整对局划分为七个可观察场景。每个场景拥有一张原创横向概念图；图片用于美术与构图基线，运行时 UI 仍由真实状态和组件绘制，不能把图片中的示意牌当成游戏数据。

| 场景 | 主要目的 | 核心交互 |
| --- | --- | --- |
| `setup.deal` | 选择起始玩家、按人数组牌并按固定顺序发完 | 无玩家动作 |
| `setup.initial-pair-sweep` | 同时移走初始对子，明确不发动技能 | 确认初始对子 |
| `turn.normal-draw` | 从顺时针最近玩家的固定牌序中暗抽 | `draw_card` |
| `pair.effect-queue` | 展示新对子、FIFO 队列和连续触发 | 结算队首效果 |
| `effect.private-exchange` | 承载偷瞄、甜蜜分享和对半交换的私密选择 | 目标、卡牌与插槽提交 |
| `player.safe` | 队列清空后确认空手玩家安全离场 | 无或继续 |
| `game.finished` | 最后一对效果结算后公开老鳖和胜负 | 再来一局 |

## 共享布局

- 桌面中央：公开对子、效果队列、跳过计数和当前提示。
- 环形座位：4–8 人按独立坐标布局；八席运行背景提供真实空间基线，未使用席位在 4–7 人局隐藏；每个对手只展示固定槽位牌背。
- 自己底部区域：完整有序牌面与合法插槽，禁止普通拖拽重排。
- 私密效果层：偷瞄结果、双方锁牌、技能插入位置，只向有权限的玩家展示。
- 右侧摘要：标准版规则、老鳖数和当前效果详解。

七张图片均为 1672×941 RGB，接近16:9。图片预留中央牌桌与 UI 安全区；移动端可使用居中 `cover` 裁切，但不能裁掉当前动作焦点，具体焦点区记录在场景目录中。

## 效果覆盖层

十类效果不各自建立独立页面，而是附着在 `pair.effect-queue` 或 `effect.private-exchange` 场景上：

- 好收成、摇匀果篮、酸住了、硬壳保护、精心理货、顺手再摘和流水果摊使用公开队列层；
- 偷瞄一串使用单人私密层；
- 甜蜜分享与对半交换使用双方锁定层；
- 技能生成对子后回到同一个 FIFO 队列，不创建嵌套页面。

## 隐藏信息

- 场景背景永远不携带真实牌面。
- 观众只接收公开槽位和队列，不接收偷瞄、选牌或随机排列映射。
- 技能插入位置公开，插入牌身份私密。
- 游戏结束前不能通过日志、重连或动画资源名称泄露老鳖位置。
