# 场景与交互建模

## 1. 场景模型定位

`model/scene-catalog.json` 将服务端阶段映射为可呈现的前端场景。场景不是第二套规则状态；它只定义进入条件、主要焦点、允许动作、公开程度和离开条件。

页面始终从最新安全快照推导场景，不能依赖上一段动画是否播放完成。断线重连后可以直接落到任意场景的稳定姿态。

## 2. 桌面总布局

```text
+--------------------------------------------------------------+
| 玩家摘要条：分数 / 车厢 / 火车站 / 当前行动者                |
+------------------------------------------+-------------------+
|                                          | 回合状态与动作     |
|               欧洲路线图                 | 公共市场 5 张      |
|        城市、轨道、车站、占用标记        | 牌库 / 弃牌数量    |
|                                          | 任务摘要 / 日志    |
+------------------------------------------+-------------------+
| 本人私有区：车票手牌、任务牌、确认/取消                      |
+--------------------------------------------------------------+
```

推荐 `roomLayout: immersive`。地图区域必须 `min-width: 0`，右栏在中等宽度降到地图下方；整个插件不能产生页面级横向滚动。

## 3. 地图层次

地图不使用官方底图时，可以在原创中性地形上按以下层次绘制：

1. `terrain-layer`：低对比陆地、水域和边界装饰，不参与命中；
2. `route-base-layer`：101 条轨道的底色、隧道边框、渡轮图标；
3. `route-owner-layer`：已占路线上的玩家车厢或连续所有权带；
4. `city-layer`：47 个城市节点与文本；
5. `station-layer`：火车站与所有者标识；
6. `interaction-layer`：合法路线光圈、焦点轮廓和大于视觉线宽的透明命中区；
7. `effect-layer`：短时动画，不持有规则数据。

轨道点击区至少 44 CSS px 宽，视觉轨道可以更细。重叠双线分别拥有独立命中形状和 `routeId`。

## 4. 核心场景

| 场景 ID | 服务端阶段 | 玩家任务 | 主要区域 |
| --- | --- | --- | --- |
| `setup.ticket-selection` | `setup_ticket_selection` | 秘密保留至少 2 张初始任务 | 私有任务抽屉、提交状态 |
| `turn.choose-action` | `turn_idle` | 在四种主行动中选择一种 | 地图、市场、动作栏 |
| `draw.train-first` | `turn_idle`（客户端抽牌模式） | 选择第一张明牌或盲抽 | 公共市场、牌库 |
| `draw.train-second` | `train_draw_second` | 选择合法第二张或自动结束 | 市场、规则提示 |
| `claim.route-select` | `turn_idle` | 选择开放轨道和支付牌 | 地图、手牌、支付预览 |
| `claim.tunnel-reveal` | `tunnel_reveal` | 查看公开风险牌，等待服务端结果 | 隧道聚焦、三张风险牌 |
| `claim.tunnel-payment` | `tunnel_payment` | 补付或放弃 | 锁定支付区、补付按钮 |
| `draw.ticket-choice` | `ticket_choice` | 从本次候选中至少保留 1 张 | 私有任务抽屉 |
| `station.build` | `turn_idle` | 选择无站城市并支付 | 地图城市、成本指示 |
| `round.final-turns` | `turn_idle` | 完成最后一轮剩余回合 | 最终轮队列、警告条 |
| `scoring.station-allocation` | `final_station_assignment` | 为已建车站选择借用轨道 | 私有任务、站点与路线预览 |
| `scoring.breakdown` | `scoring` | 查看逐项结算 | 计分表、任务翻开 |
| `game.finished` | `finished` | 查看名次和再来一局 | 获胜者、完整明细 |

`claim.route-select` 与 `station.build` 是 `turn_idle` 上的交互模式，而非额外服务端阶段。用户取消选择时不需要网络请求。

## 5. 场景进入与离开

### 5.1 初始任务选择

- 进入：服务端已经发出本人 4 张任务候选；
- 交互：勾选 2 至 4 张，其他玩家只看到“已提交/未提交”；
- 离开：所有有效玩家提交，服务端选定首家并进入 `turn_idle`；
- 隐私：候选端点、类别、分值和放弃内容只对本人可见。

### 5.2 抽取车票牌

- 第一次选择后，服务端立即更新市场；
- 如果拿到公共彩虹，直接结束回合；
- 如果第一张来自其他来源，则进入第二张场景；
- 第二张场景把公共彩虹设为不可用，并解释原因；
- 牌库与市场都无法提供牌时，动作入口整体不可用。

### 5.3 占用普通轨道或渡轮

- 地图先显示服务端给出的 `claimableRouteIds`；
- 选中轨道后，手牌根据颜色、长度和渡轮最低彩虹数分组；
- 提交前显示将消耗的牌、车厢和即时得分；
- 服务端确认后，播放支付牌离场与车厢落位动画；
- 服务端拒绝时保留本地选择并提示重新核对，不预先修改版图。

### 5.4 隧道

```text
选择隧道与初始支付
        |
        v
服务端锁定支付并揭示最多 3 张
        |
        +-- 额外费用 0 --> 自动成功 --> 回合结束
        |
        +-- 额外费用 >0 --> 补付 / 放弃 --> 回合结束
```

揭示动画只展示服务器已返回的具体牌。动画播放期间可临时锁住本地按钮，但重连时直接显示 `pendingTunnel` 的稳定结果。放弃按钮必须明确说明“初始支付牌退回，揭示牌弃掉，本回合结束”。

### 5.5 任务牌选择

- 候选牌只渲染在本人私有抽屉；
- 未选择 1 张时禁用提交；
- 提交前显示“保留后不能弃掉”；
- 提交完成后，公共事件只说玩家新增了几张任务牌，不公开拿到或放回哪些牌。

### 5.6 火车站

- 只高亮当前没有任何车站的城市；
- 成本按本人已建站数量自动显示为 1、2 或 3；
- 支付选择复用车票牌组件；
- 建造时不需要立刻选择借用路线；
- 终局分配场景才显示该站所有合法对手路线与任务完成预览。

## 6. 玩家摘要

每名玩家的公开摘要包含：

- 昵称与稳定座位色/纹样；
- 当前分数；
- 剩余车厢；
- 剩余未建火车站；
- 车票手牌数量；
- 任务牌数量；
- 是否当前行动、断线、弃权或已完成最终回合。

摘要不能显示对手长程任务数量，也不能从卡背样式推断。

## 7. 移动端

- 地图固定在可平移缩放的视口，初始自动框选当前相关城市；
- 本人手牌使用底部抽屉，打开后可压缩地图高度但不改变逻辑坐标；
- 四种行动使用明确文字，不只放图标；
- 轨道可从按长度、颜色、类型分组的无障碍列表中选择；
- 双线选择显示端点、颜色和“轨道 A/B”，避免两条细线难以点选；
- 任务与车站预览可全屏显示，关闭后保持之前地图缩放；
- 在 320 px 宽度下按钮仍至少 44 x 44 CSS px。

## 8. 动画事件

| 事件 | 建议表现 | 可跳过 |
| --- | --- | --- |
| `train_card_drawn` | 市场牌滑入本人区域，空位补牌 | 是 |
| `market_refreshed` | 5 张牌整体淡出再补入 | 是 |
| `route_claimed` | 车厢沿路线依次出现，分数滚动 | 是 |
| `tunnel_cards_revealed` | 最多 3 张依次翻开，匹配牌高亮 | 是 |
| `tunnel_declined` | 初始支付回手，风险牌进入弃牌 | 是 |
| `station_built` | 城市节点升起站标志 | 是 |
| `final_round_started` | 顶部显示最后一轮队列 | 否，状态提示持续存在 |
| `tickets_revealed` | 终局逐张标记完成或失败 | 是 |
| `european_express_awarded` | 最长路线高亮并加 10 分 | 是 |

事件只引用公开数据或当前查看者有权知道的数据。同一服务端事件可以为不同视角生成不同文本。

## 9. 无障碍与替代表达

- 每条轨道的可访问名称包括端点、长度、颜色、类型、占用者和是否关闭；
- 颜色同时使用纹样与文字，灰色中性轨道明确读作“任意单色”；
- 隧道使用拱门轮廓，渡轮使用锚形标记，不只换颜色；
- 地图提供键盘模式：按城市浏览相邻轨道，Enter 选择；
- 当前行动者、最终轮和隧道费用变化通过 `aria-live` 播报；
- 减弱动态效果开启时，用淡入和静态高亮替代滑动、翻转与路径流光；
- 所有结果表格都能以纯文本读取，不依赖地图视觉。

## 10. 场景与安全视图关系

```text
权威 GameState
      |
      v
visibility.project(viewer)
      |
      v
安全 ViewState + actions[] + focus
      |
      v
scene-catalog 选择 sceneId
      |
      v
Vue 组件渲染 + 非权威动画
```

前端不得根据 `phase` 猜测隐藏候选。只有安全视图实际含有 `private.pendingTicketChoice` 或 `private.pendingTunnelPayment` 时，才显示对应私有操作。

## 11. 验收场景

1. 三名玩家中两人已提交初始任务选择，第三人仍只能看到自己的候选和他人的提交状态。
2. 第一张明抽普通牌后市场补出彩虹；第二张场景正确禁用该彩虹。
3. 市场因三张彩虹连续刷新两次，动画可跳过且最终状态一致。
4. 2 人局一条双线被占后，另一条显示“关闭”而不是“已占”。
5. 5 人局一名玩家不能拿同组第二条，但其他玩家仍可拿。
6. 渡轮支付不足最低彩虹数时，确认按钮与服务端都拒绝。
7. 隧道揭示后断线重连，仍显示同样三张风险牌和相同额外费用。
8. 隧道放弃后初始牌回手，风险牌消失到弃牌堆，轨道仍开放。
9. 终局站点分配仅本人看到任务完成预览；他人只看到“正在选择”。
10. 最长路线并列时所有并列玩家都获得 10 分，结果表可读出原因。
11. 观众在终局前看不到任何手牌或任务牌 ID，终局后只看到规则允许公开的结果。
12. 320 px 触屏和纯键盘均能完成四类主行动与所有子流程。
