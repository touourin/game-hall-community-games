# 场景与交互模型

## 1. 设计目标

场景需要在 2–4 人下同时支持计牌、隐藏手牌、快速目标选择和私密效果。视觉层级从高到低是：当前强制选择、自己的手牌、当前行动与目标、公开出牌历史、整局好感进度、装饰背景。

结构数据位于 `model/scene-catalog.json`，原型见 `assets/table-scene.svg`。

## 2. 逻辑画布

宽屏按 `1600 × 900` 逻辑像素设计：

- 上方 `status_bar`：规则档案、轮数、当前行动提示和牌堆数量。
- 外圈 `seat_1` 至 `seat_3`：相对本人座位顺时针排列的对手。
- 下方 `self_seat`：本人名称、好感、保护／淘汰状态与手牌。
- 中央 `court_table`：牌堆、暗置牌、两人公开移除牌及最近动作。
- 各座位旁 `history_*`：按时间公开排列该玩家打出／弃掉的牌。
- 顶层 `choice_overlay`：目标、卫兵猜测、大臣排序和私密查看。
- 顶层 `result_overlay`：轮末和整局结果。

座位以观察者为相对 0 号。对手按实际座次旋转映射，不能把固定 `p1` 永久放在底部，否则不同玩家视图会颠倒操作习惯。

## 3. 人数布局

- **2 人**：对手居上，本人在下；公开移除三张牌在中央左侧持续展示。
- **3 人**：两名对手分居左上、右上。
- **4 人**：对手位于左、上、右。

每个座位显示：头像／名称、好感标记、手牌张数、本轮状态、侍女保护、最近公开牌和可展开完整历史。

## 4. 核心场景

### 4.1 `round_setup`

显示洗牌、暗置、两人局公开移除和逐人发牌。动画只表现数量与去向，不在客户端预先生成牌序。完成后焦点落在首家提示。

### 4.2 `turn_draw`

当前玩家的牌堆按钮成为主操作；其他玩家看到等待状态。若侍女保护到期，先播放短暂护罩消退提示。

### 4.3 `turn_play`

本人两张手牌上移展开。合法牌带按钮语义；伯爵夫人强制时，其他牌仍保持可读但禁用，并显示中性原因“受出牌规则限制”，不泄漏额外信息给他人。

### 4.4 `target_choice`

合法座位出现编号、轮廓和文字按钮，受保护／已淘汰玩家明确显示不可选原因。卫兵先选目标，再在同一面板选角色；也可先选角色，但一次提交必须包含两项。

### 4.5 `private_reveal`

牧师只向行动者展示目标手牌；男爵向双方展示比较牌面。浮层包含“仅你可见”或“仅比较双方可见”，关闭后私密日志保留带时间戳的历史记录。

### 4.6 `chancellor_choice`

候选牌最多三张，分为“保留区”和“牌底顺序区”。拖拽不是唯一输入方式：每张牌有“保留”“移到牌底第 1／2 张”按钮，并支持方向键重排。确认前显示最终顺序解释。

### 4.7 `elimination`

被淘汰者手牌翻到其公开历史，座位转为低饱和并显示“本轮出局”。公主、卫兵、男爵等原因以文字事件说明；减少动态模式只做轮廓与状态切换。

### 4.8 `round_result`

显示结束原因、仍在局手牌（最后一张封存时）、轮胜者、间谍资格、每人的标记变化和下一轮首家候选。封存牌只显示牌背，不发送或展示身份。先完成所有奖励分项，再更新整局进度条。

### 4.9 `game_result`

显示全部共同胜者、最终好感标记和逐轮摘要，不使用只支持单胜者的奖杯文案。

## 5. 选择与反馈

- 所有选项来自安全视图，不在浏览器重算合法性。
- 提交动作后锁定对应控件，直到收到更高 revision 或明确错误。
- 过期选择返回“桌面已更新，请重新选择”，并刷新候选。
- 卫兵猜测未命中只显示“猜测不符”，绝不翻开目标手牌。
- 卫兵猜中皇后时显示“皇后防卫：弃牌重抽”，保持目标座位为在局状态，并播放重抽而非淘汰反馈。
- 牌效无合法目标时，短暂停留卡面并显示“没有合法目标，效果略过”。
- 当前玩家始终有单一主操作；不可操作的观察者不显示伪按钮。

## 6. 动画语义

动画由服务端 `eventSeq` 驱动：

| 事件 | 动画 | 减少动态 |
| --- | --- | --- |
| 抽牌 | 牌背从牌堆滑向手牌 | 手牌区域淡入计数变化 |
| 打出 | 卡牌从手牌移到本人历史 | 原位置与目标位置描边 |
| 查看 | 私密信封打开 | 无位移淡入 |
| 比较 | 两张牌靠近天平 | 同时描边后显示结果 |
| 保护 | 半透明封蜡护罩环绕座位 | 常驻盾牌图标 |
| 强制弃牌 | 手牌移到公开历史 | 目标区高亮并立即公开 |
| 交换 | 两个密封信封交叉 | 两座位同时脉冲，不画轨迹 |
| 压回牌底 | 候选按确认顺序移向牌堆 | 顺序标签消失并更新计数 |
| 淘汰 | 封蜡破裂、座位降饱和 | 直接切换状态并播报 |
| 获得好感 | 标记从中央落到座位 | 数字递增并描边 |

重连客户端不重播旧事件，直接渲染快照；只播放 `eventSeq` 大于本地已确认值的事件。

## 7. 响应式布局

### 宽屏（≥1180px）

保留环形牌桌；对手公开历史直接可见；选择面板从右侧抽屉出现。

### 中屏（760–1179px）

座位压缩为名牌和最近两张公开牌，点击可展开历史；选择面板覆盖中央下半部。

### 紧凑屏（≤759px）

改为纵向结构：顶部对手横向轨道、中部公共牌堆与最近动作、底部固定本人手牌和主操作。选择面板使用底部 sheet，页面根节点不横向滚动。

### 窄屏（≤359px）

隐藏装饰纹样，角色卡使用紧凑文字，公开历史在自己的容器内滚动；按钮最小触控区域仍为 `44 × 44` CSS 像素。

## 8. 无障碍

- 角色以“点数＋名称＋效果”读出，不只读图标。
- 当前玩家、保护和淘汰均有文字标签与 `aria-live` 播报。
- 手牌、目标和大臣排序全流程可用键盘完成。
- 私密浮层打开时正确圈定焦点，关闭后返回触发控件。
- 不用颜色单独表达合法、命中、淘汰或胜利。
- 支持 `prefers-reduced-motion`，所有位移动画可替换为淡入或描边。
- 正文对比度至少 4.5:1，焦点轮廓至少 3:1。

## 9. 原创资产边界

场景使用通用信笺、封蜡、宫廷几何纹样和抽象符号。不得抓取或描摹官方角色插画、Logo、卡背和版式。发布级图标应在授权确认后单独制作；本包 SVG 只验证信息架构、尺寸和状态层级。
