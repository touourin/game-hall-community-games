# 方格游戏（2 人 / 4 人）

支持双人和四人联机的 Blokus 风格铺块游戏。每位玩家都持有相同的 21 块棋块（89 个单位格）：双人局使用 14×14 棋盘，从两个中心起点展开；四人局使用 20×20 棋盘，从四角向中央延伸。

## 玩法

1. 房间恰好 2 人或 4 人时可以开始；3 人时需等待第 4 人。每局开始和每次再来一局都会重新随机玩家顺序，然后按该顺序分配颜色、起始点和回合顺序。
2. 双人局使用 14×14 棋盘，蓝、黄双方起点分别位于第 5 行第 5 列和第 10 行第 10 列，即零基坐标 `(4, 4)`、`(9, 9)`。四人局使用 20×20 棋盘，蓝、黄、红、绿依次从左上、右上、右下、左下四角开始。
3. 每回合放一块。首块必须覆盖自己的起始点；后续棋块必须与已有同色棋块至少角接一次，不能与任何同色棋块边接。
4. 可按 90° 旋转和镜像翻转。不同颜色可以边接或角接；不能重叠、越界，也不能移动已落棋块。
5. 服务端穷举剩余棋块的全部不同方向。确实无合法落点或已放完的玩家自动跳过，不能主动过牌。其他人继续，直到所有人都不能再放。
6. 桌面端使用大厅的浏览器宽幅沉浸布局，并在一个浏览器首屏内组成单页操作台：棋盘在左，旋转、翻转、找落点、方向微调、确认按钮和紧凑棋块库在右，无需向下滚动即可完成回合。保留网页顶部控制、聊天和正常页面边界，不调用系统全屏。1000px 及以下窗口改为适合手机的上下布局，仍可放大、滚动棋盘。棋盘聚焦时支持方向键、R 旋转、F 翻转、Enter 确认和 Esc 取消。
7. 棋块库公开，可以点击玩家卡查看其全部 21 块的使用情况。观战者没有任何落子或重新开局权限。

## 排名与积分

按剩余**小方格数**由少到多排名，不是按剩余棋块数量直接排名。

| 模式 | 第一名 | 第二名 | 第三名 | 第四名 |
| --- | ---: | ---: | ---: | ---: |
| 2 人 | +2 | +1 | — | — |
| 4 人 | +2 | +1 | 0 | −1 |

为保证独立名次，本平台补充：剩余格数相同则剩余块数少者优先；仍相同则本局随机出手顺序较后者优先。这里不使用官方版本的放完奖励分。第一名记为冠军，其他名次保留各自积分，不按胜负统一换算。

主动退出或掉线超时（沿用大厅的重连宽限期）视为弃权，已落棋块保留。弃权者排在所有未弃权者之后；多人弃权时先弃权者名次更后。只剩一位未弃权玩家时立即结束。短暂断线期间保留回合和全部棋块，正常重连可继续。

插件使用现有 API v1 的 `records.scoreKind = "outcome"`，不新增宿主成绩类型、不修改主项目或数据库结构。`player_result()` 将名次和单局分写入战绩身份文字，个人历史显示例如「第 2 名 · +1 分」或「第 4 名 · -1 分」；结算原因包含本局全部玩家的名次和积分，在大厅原有的对局详情中也能查看。

`player_score()` 返回上表中的有符号单局积分，宿主原有的保存流程会将其写入 `score_value`；`record_state()` 同时保留完整排名和分数字典。0 和负数不会丢失，重复保存同一局不会创建重复战绩。大厅排行榜仍按既有胜负规则统计，第一名记胜，其余记负；**不提供跨局累计积分榜**，单局名次分由游戏结算界面和战绩说明展示。

含游客的对局可以正常游玩并显示名次积分，但沿用大厅政策不保存账号战绩，也不计入排行榜。本游戏不支持 AI、悔棋、求和或录像回放。

## 完整棋块目录

前后端共用 [`pieces.json`](pieces.json)，`#` 为占用格、`.` 为空格，每种棋块每人一份。21 种形状包括 1 个单格块、1 个双格块、2 个三格块、5 个四格块和 12 个五格块。所有旋转和翻转均属于原棋块，不增加库存。

| 格数 | 棋块编号 |
| ---: | --- |
| 1 | M1 |
| 2 | D2 |
| 3 | I3、L3 |
| 4 | I4、O4、T4、L4、Z4 |
| 5 | F5、I5、L5、N5、P5、T5、U5、V5、W5、X5、Y5、Z5 |

## 动作与状态协议

`place` 的 payload：

```json
{ "pieceId": "L5", "x": 0, "y": 0, "rotation": 0, "flipped": false, "turnNumber": 1 }
```

- `x/y`：变换后棋块外接矩形左上角；双人棋盘范围为 0–13，四人棋盘范围为 0–19，不是鼠标像素。
- `rotation`：0–3 整数，表示顺时针旋转次数。`flipped`：布尔值，先水平翻转再旋转，最后将形状归一到左上角。
- `turnNumber`：当前快照的回合编号。防止旧请求、重复提交或重连前的操作落在新回合。
- 服务端校验真实房间成员、对局阶段、当前玩家、未使用的棋块、参数类型以及所有落子规则。客户端预览不作为裁判。
- `resign` / `manual_forfeit()` / `disconnect_timeout()` 走相同弃权排序逻辑，不允许借弃权清空棋盘。

视图返回 `mode`、`boardSize`、`board`（14×14 或 20×20，−1 为空，0–3 对应按本局随机顺序分配的蓝黄红绿）、`players`（颜色、起始点、剩余棋块与格数、状态、名次和积分）、`currentPlayerId`、`turnNumber`、`moveCount`、`lastMove`、自动跳过/弃权动态、最终 `rankings` 和 `rankPoints`。完整回合记录保存在结算快照中；公共快照不泄漏任何账号凭证。

## 图标身份

核心识别物为四角向内铺展的多格骨牌棋盘，加一块略悬起的 L 形块；轮廓为低矮方盘 + 错落方格块。采用大厅的双层圆角基座、三分之四俯视棚拍风格，唯一点缀色为低饱和钢蓝，阵营四色只用于对局 UI。深浅两个材质版本保持同一构图。

图标使用内置 imagegen 制作，最终文件为 `frontend/assets/catalog-dark.webp` 与 `frontend/assets/catalog-light.webp`（768×768，RGB，WebP quality 90）。完整提示词见 [artwork-prompts.md](artwork-prompts.md)。在 142、104、72px 三种尺寸下与五子棋、舒尔特表、俄罗斯方块的深浅图标分别并排验收；中间图与检查图不加载到运行时。

## 验证

后端测试分别覆盖 14×14 双中心开局和 20×20 四角开局、完整多格骨牌集合、所有变换、每局随机顺序、同色边接/角接、异色接触、越界重叠、参数伪造、回合重放、自动跳过、自然终局、弃权、同分排序和两套积分。前端覆盖两种棋盘、预览、变换、找落点、提交去重、回合切换及观战权限。插件自己的集成测试验证双人和四人积分持久化、原有胜负统计、战绩文字中的 0 和负分、重复保存及游客局排除。

在主项目根目录运行 `python scripts/test_community_games.py`；前端执行 `npm --prefix frontend run test:run` 与 `npm --prefix frontend run build`。

接入只需本社区仓库的 `registry.json` 注册项和 `plugin-blokus/` 目录，无需主项目配套 PR、SDK 扩展或数据库迁移。详细本地验收记录见 [validation.md](validation.md)。

## 规则来源

- [Mattel Blokus Duo 说明书 FWG43](https://service.mattel.com/instruction_sheets/FWG43-Eng.pdf)：14×14 棋盘、42 块棋块、两个中心起点及双人落子规则。
- [Mattel Blokus 说明书 BJV44](https://service.mattel.com/instruction_sheets/BJV44-Eng.pdf)：棋块、四角起步、同色角接、无法落子和终局规则。
- [Mattel Blokus 说明书 X3128](https://service.mattel.com/instruction_sheets/X3128-ENG.pdf)：20×20 棋盘及蓝黄红绿回合顺序。

本插件为独立实现，使用原创界面与棋块绘制；每局随机顺序、积分、同分和弃权排序是本平台补充规则，不宣称为官方赛事规则。
