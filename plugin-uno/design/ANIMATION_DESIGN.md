# 功能牌动画与演出分镜

## 总体原则

动画必须先表达规则，再表达气氛。玩家应在 300ms 内看懂“谁被影响、方向如何改变、要摸几张”，完整演出不超过 1.55 秒，且不阻塞输入或修改权威状态。

服务端通过 `latestEvent.sequence` 输出一次性事件；前端根据 `type` 创建新的 `EffectOverlay`。所有覆盖层使用 `pointer-events: none`，事件生效与动画播放完全解耦。

## 关键帧节奏

### 跳过

1. `0–120ms`：画面中心压暗，切片线出现。
2. `120–360ms`：禁止符号从旋转 -150°、缩放 0.08 进入。
3. `360–620ms`：符号定格；文本明确显示被跳过者。
4. `620–980ms`：所有层向外扩散并淡出。

### 反转

1. 服务器先更新 `direction`。
2. 覆盖层环从旧方向快速减速。
3. 中心双箭头过冲并反向旋转。
4. 覆盖层消失时，常驻桌面方向轨道已按新方向运动。

### 万能 `+4`

1. `0–180ms`：中心吸入，背景亮度降至 44%。
2. `180–430ms`：`wild-draw-four-burst.png` 从 0.16 倍扩到 1.02 倍。
3. `300–760ms`：中心 `+4`、当前累计总数、玩家与目标文案同时可读。
4. `760–1150ms`：惩罚反应堆持续脉冲，提示目标可以叠牌或接牌。
5. `1150–1550ms`：光环扩散，牌桌边缘落在已选择的颜色。

### 惩罚链与接牌

1. 每张 `+2 / +4` 仍显示本张贡献值，避免把“本张 +4”误读成“单牌 +8”。
2. 当 `stackTotal > count` 时，功能牌右上方额外显示“累计 +N”徽标。
3. 动画结束后，牌桌下缘的常驻惩罚反应堆继续显示总数与锁定玩家。
4. 玩家选择接牌后，`take_penalty` 演出显示最终总数；状态先由服务端结算，演出不延迟下一位玩家状态。

## 文件映射

- 状态事件：`backend/engine.py::_emit`
- 演出容器：`frontend/components/EffectOverlay.vue`
- 关键帧：`frontend/animations/effects.css`
- 卡牌选择、摸牌：`frontend/components/PrismCard.vue`
- 桌面常驻方向动画：`frontend/GameView.vue`
- 机器可读节奏：`design/animation-cues.json`

## 减少动态模式

当系统启用 `prefers-reduced-motion: reduce`：

- 关闭高速射线、旋转环、轨道旋转与卡牌弹性位移。
- 隐藏透明粒子爆发素材。
- 功能牌只显示中心规则符号、标题和事件文本，700ms 淡入淡出。
- 状态变更、按钮焦点与颜色提示不受影响。

## 后续音频接口建议

本版未加入音频文件。后续可按事件 ID 加入：

```text
play.soft
skip.slice
reverse.orbit
draw.penalty.2
draw.penalty.stack
draw.penalty.take
wild.spectrum
wild.penalty.4
uno.call
uno.caught
```

音频应在玩家首次交互后解锁；观战者默认较低音量；减少动态模式不必静音，但应避免强低频连续轰鸣。
