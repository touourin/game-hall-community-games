# 测试覆盖矩阵

测试分为服务端规则、组件交互、真实引擎浏览器壳、确定性整局压力测试和宿主集成五层。下列每个结算条件均有独立断言，不依赖随机跑局“碰巧覆盖”。

## 规则与结算

| 分组 | 覆盖情况 |
| --- | --- |
| 初始化 | 2、3、4、5、6 人全部发完 56 张；轮流发牌差不超过 1；随机起点；指定房主先手；拒绝 1/7 人、非连续座位、离房玩家和非标准规则档案 |
| 正确铃条件 | 单张 5；2+3；1+1+3；两种水果同时为 5；覆盖旧顶牌后从 8 变 5 |
| 非正确铃 | 0、4、6、10；不同水果合计为 5；被覆盖的旧牌不参与；服务端不信任客户端计数 |
| 翻牌 | 非当前玩家、无牌、过早、旧 revision、旧 boardEpoch、动作幂等、按顺序选择下一位可翻者 |
| 标准正确铃 | 收走所有完整明牌堆；按响铃者座位开始顺时针入堆底；清空桌面；响铃者成为下一翻牌者；桌面版本递增 |
| 标准误按 | 向所有其他在局者各付一张；顺时针支付；牌不足时部分支付；自己抽牌耗尽时退出；桌面顶牌与 boardEpoch 不变 |
| 最后机会 | 抽牌空但自己的明牌尚在仍能抢铃；抢对后收牌复活；自己的明牌被他人收走后退出；误按后退出 |
| 最终二人 | 两人开局立即武装；3→2 的当前铃不结束；下一次正确铃结束；下一次错误铃由对手收走全部明牌并结束 |
| 胜负 | 最高总持牌获胜；相同最高数共享胜利；所有结果行总数恒为 56；退出和无进展结算原因正确 |
| 无进展 | 无人可翻且无正确铃时建立 10 秒期限；未到期拒绝；到期结算；若仍存在正确铃则拒绝安全裁决 |
| 竞态与安全 | 6 个并发铃仅首个结算；同桌面后到请求无处罚；旧桌面请求无处罚；actionId 跨重试幂等；视图不泄漏暗牌 ID、牌序或自动水果合计 |
| 守恒 | 每次动作后恰有 56 个唯一实例；状态篡改能够触发不变量保护；断线、主动退出和宿主强退路径 |

## 前端与动画

| 分组 | 覆盖情况 |
| --- | --- |
| 牌面 | 4 种 SVG 形状、1–5 布局、20 个目录牌面、牌背、可访问名称、非纯颜色区分 |
| 主操作 | 铃的 pointer/touch/keyboard/button 输入；重复 pointer+click 抑制；F/Space/R/Escape 快捷键；观战只读；翻牌等待倒计时 |
| 事件队列 | 历史初始化只播放最新事件；后续按 seq 串行；桌面版本变化解除本地铃去重；动作失败恢复 |
| 动画 | `round_deal`、`card_flip`、`bell_press_local`、`bell_confirmed`、`collect_piles`、`penalty_transfer`、`player_eliminated`、`final_duel_armed`、`result_enter` |
| 响应式 | 2–6 人席位；宽屏椭圆；紧凑对手矩阵；320/375/768/1024/1440 px；无页面水平溢出；中央铃点击目标不少于 64 px |
| 穿模保护 | 运动层 `pointer-events:none`；桌面裁剪；铃层高于移动牌；规则与结果遮罩高于牌桌事件；动画中仍可命中铃 |
| 无障碍 | 焦点轮廓、动态播报、减少动态效果、非颜色状态文字、按钮语义和最小点击目标 |

## 整局矩阵

`tools/run_local_matrix.py` 对每个人数使用互不重叠、可复现的 seed 区间。自动玩家只根据服务端公开状态行动：满足恰好五个时正确响铃，否则继续翻牌；当无法推进时执行安全裁决。每局结束都再次检查 56 张守恒、终局阶段和有效赢家。

实际命令、通过数量、seed 和浏览器尺寸记录在 [`LOCAL_TEST_REPORT.md`](LOCAL_TEST_REPORT.md)。
