# 《算途疾行》场景模型

> 场景、镜头、材质与响应式布局规格 v1.1

## 1. 设计目标

《算途疾行》把每一道算式题变成一次正在逼近的十字路口。玩家不是在静态答题卡上选择答案，而是在持续奔跑的场景中读取 2–4 块方向题牌，并在到达路口前选出唯一成立的等式。

场景模型遵守四个原则：

1. **先读路，再读题**：开放路线、封闭障碍和方向位置必须在 320 px 宽度下仍可一眼分辨。
2. **运动不影响计算**：跑道可以制造速度感，题牌本身不抖动、不倾斜文字、不经过高频闪烁。
3. **主题只换材质**：几何、布局与交互保持一套，通过宿主主题令牌改变天空、跑道、金属、雾和语义色。
4. **服务端决定结果**：场景只表现服务端题目、剩余时间和结果，不能自行判定正确方向。

## 2. 世界设定

场景位于云层上方的“算轨学院”：一组悬浮的模块化跑道连接观测塔与几何庭院。建筑只提供纵深和节奏，不参与规则。

- 主跑道：深色复合石板与金属导轨组成的连续窄桥。
- 十字节点：圆形罗盘底盘连接上、下、左、右四个路线接口。
- 题目闸门：每条开放路线前悬浮一块磨砂玻璃题牌。
- 障碍封锁：未开放路线使用带斜纹的实体几何挡板，不只依靠颜色表示。
- 远景：低对比观测塔、环形桥与云海；不放可误认成路线的高亮结构。

## 3. 场景层级

```text
scene-root
├── sky-layer             天空渐变、云海与远景雾
├── architecture-layer    低对比观测塔和悬浮结构
├── track-world           透视跑道、滚动板块和边缘导轨
│   ├── approach-strip    从玩家到路口的接近段
│   ├── junction          十字节点
│   ├── route-up
│   ├── route-left
│   ├── route-right
│   └── route-down        以近景回转入口表达“下”
├── gate-layer            四向题牌与障碍
├── runner-layer          玩家模型与接触阴影
├── effects-layer         速度线、答对波纹、升级光环
└── hud-layer             等级、连对、分数、倒计时
```

`hud-layer` 不参与场景透视；所有等式使用水平排版，保证乘号、除号和括号清晰。

## 4. 坐标与镜头

逻辑画布使用归一化坐标：左上角 `(0, 0)`，右下角 `(1, 1)`。

| 元素 | 桌面中心 | 手机中心 | 说明 |
| --- | --- | --- | --- |
| 消失点 | `(0.50, 0.28)` | `(0.50, 0.25)` | 始终位于上方向题牌下方 |
| 十字节点 | `(0.50, 0.48)` | `(0.50, 0.43)` | 手机为控制区留出底部空间 |
| 跑者落脚点 | `(0.50, 0.79)` | `(0.50, 0.73)` | 角色不遮挡下方向题牌 |
| 上题牌 | `(0.50, 0.18)` | `(0.50, 0.16)` | 水平居中 |
| 左题牌 | `(0.19, 0.43)` | `(0.18, 0.42)` | 向画面中心内收 |
| 右题牌 | `(0.81, 0.43)` | `(0.82, 0.42)` | 与左题牌镜像 |
| 下题牌 | `(0.50, 0.67)` | `(0.50, 0.64)` | 放在跑者前方，不放在角色身后 |

镜头为略俯视的第三人称追逐镜头，等效视场角约 `52°`。路口接近过程只改变跑道纹理位移和节点比例，不改变题牌文字的可读角度。

## 5. 响应式布局

### 5.1 桌面端（≥ 900 px）

- 插件接管一个完整动态视口，根节点固定为 `100dvh`，HTML 与 Body 在组件存续期间锁定滚动。
- 顶部 HUD 显示等级、连对、最大路程榜值和技巧分；主区域使用“跑道 + 右侧控制台”布局。
- 四向键盘提示贴在对应题牌角落：`W / A / S / D`。
- 四向控制板保持可见但降低视觉权重，方便鼠标操作和无障碍键盘聚焦。

### 5.2 平板与手机（< 900 px）

- 手机采用横屏驾驶舱；纵屏时只显示明确的旋转提示，不在狭窄纵屏中挤压题牌。
- 横屏左侧为完整四向跑道，右侧为固定触控控制台，顶部 HUD 压缩为四列。
- 四向按钮最小 `44 × 44 CSS px`，并通过安全区内边距避开刘海和系统手势区域。
- 页面宽高均锁定为动态视口，不出现浏览器边缘的纵向或横向滚动条。
- 等式字号按跑道可用宽度缩放，题牌最小点击高度为 `43 CSS px`。

## 6. 主题材质映射

场景通过 `usePluginTheme()` 读取宿主材质，不自行修改主题。

| 场景部件 | 宿主材质 | 用途 |
| --- | --- | --- |
| 天空上/下渐变 | `scene.top / scene.bottom` | 云上环境底色 |
| 跑道表面 | `stage.top / stage.bottom` | 石板明暗面 |
| 导轨与节点边缘 | `stage.edge / stage.innerEdge` | 几何轮廓 |
| 题牌玻璃 | `metal.glass / metal.glow` | 开放方向展示面 |
| 正确反馈 | `semantic.success*` | 结果已由服务端确认后使用 |
| 错误/超时反馈 | `semantic.danger*` | 失败结果与障碍警示 |
| 时间不足 | `semantic.warning*` | 最后 25% 时间预警 |

开放与封闭不能只靠颜色：开放路线同时具有题牌、箭头和可点击状态；封闭路线同时具有实体挡板、斜纹和“封闭”读屏文本。

## 7. 深度与可读性

- 远景对比度不超过主要题牌对比度的 45%。
- 题牌后方必须有半透明深/浅底，不直接把算式压在云层上。
- 速度线避开题牌安全矩形，数量随等级从 4 增至 12，但透明度不超过 0.22。
- 跑道纹理滚动速度随等级加快；几何节点本身不做高频缩放，避免眩晕。
- 倒计时最后 25% 只使用边框呼吸和数值变化，不整屏闪烁。

## 8. 场景状态

| 状态 | 跑道 | 跑者 | 题牌 | 输入 |
| --- | --- | --- | --- | --- |
| `approaching` | 持续向后滚动 | 循环奔跑 | 2–4 块可读 | 开放 |
| `committing` | 短暂加速 | 向所选方向压身 | 所选题牌锁定 | 本地锁定 |
| `turning` | 场景横移/偏航 | 90° 转向动作 | 上题淡出、下一题准备 | 锁定至新快照 |
| `level-up` | 导轨产生一次波纹 | 继续奔跑 | 新等级标记淡入 | 开放 |
| `failed-wrong` | 在路口停止 | 失衡刹停 | 显示正确方向 | 关闭 |
| `failed-timeout` | 障碍闭合 | 急停 | 显示“超时”与正确方向 | 关闭 |
| `completed` | 终点平台出现 | 冲线减速 | 隐藏 | 关闭 |

## 9. 性能边界

- 运行时场景只使用 DOM/CSS 变换与渐变，不加载设计稿作为动态背景。
- 动画只改变 `transform`、`opacity` 和自定义属性，避免逐帧布局。
- 同屏最多 12 条速度线、4 块题牌、4 个障碍和 1 个角色。
- 页面隐藏或组件卸载时清理倒计时与键盘监听。
- `prefers-reduced-motion: reduce` 时停止跑道滚动、速度线和角色肢体循环，只保留 120–180 ms 的状态淡入。

## 10. 验收标准

1. 桌面 `1440×900`、`1280×720` 与手机横屏 `844×390`、`667×375` 均无页面级横向或纵向滚动。
2. 四个方向的位置在所有尺寸保持稳定；`下` 方向不会被角色或控制板遮挡。
3. 两、三、四选项题都能明确区分开放路线与障碍。
4. 四套宿主主题中，题牌正文与背景满足清晰可读，不依赖单一颜色表达结果。
5. 减弱动态效果开启后仍能完成全部操作。
6. 重连可直接进入当前服务端状态，不要求补播历史动画。
7. 手机纵屏显示旋转提示，转为横屏后无需刷新即可进入可操作驾驶舱。
