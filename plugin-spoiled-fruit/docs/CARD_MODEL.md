# 卡牌模型

## 身份与数量

`model/card-catalog.json` 是卡牌身份、数量、效果和图片路径的唯一事实来源：

- `fruit-01` 至 `fruit-30` 各有 2 个物理实例，共 60 张；
- `old-maid-01` 至 `old-maid-04` 各有 1 个实例，4–8 人依次加入 2、2、3、3、4 张；
- 正常牌只有 `pairKey` 完全相同才能组成对子；不同老鳖的 `pairKey` 均为 `null`；
- 每个正常对子只对应一种 `effectId`。

运行时卡牌实例 ID 建议为 `fruit-01-a`、`fruit-01-b` 与 `old-maid-01`。目录中的主体图只生成一次，两张相同水果牌复用同一图片，以保证真正完全相同。

## 卡面渲染

推荐卡面比例为 2:3，图片不是完整牌面截图，而是透明主体素材。前端按以下层级组合：

1. 效果类别底色与圆角边框；
2. 左右上角的两位水果编号；
3. 中央透明水果 PNG；
4. 水果中文名称；
5. 效果图标、效果名称和精确规则短句；
6. 需要时显示保护、已知位置或待结算状态覆盖层。

中文和规则文本必须由 HTML/CSS 或矢量文本绘制，不能烧录进生成图，避免错字和小字号模糊。所有隐藏牌统一使用 `assets/cards/card-back.png`，不得根据真实身份选择不同牌背。

## 固定牌序

- 权威手牌使用 `handCardIds: string[]`，数组 0 是最左侧。
- 初始发牌和正常暗抽只能 `append` 到数组末尾。
- 移除牌后其余元素保持相对顺序。
- 甜蜜分享、对半交换和流水果摊的接收者提交插入槽与多牌相对顺序。
- 只有“精心理货”可以移动一个既有元素；“摇匀果篮”由服务端生成整组随机排列。
- 对手视图只公开稳定的槽位与数量，不公开牌面；普通客户端不得提交任意重排。

## 图片约束

- 30 张正常水果与 4 张老鳖均为 1254×1254 RGBA，并具有真实透明区域。
- 统一牌背为 1024×1536 RGB，纵向2:3。
- PNG 保留原始生成尺寸；运行时通过 `object-fit: contain` 缩放，不裁切水果轮廓。
- 若替换图片，需保持文件名或同步修改卡牌目录，并重建资源清单。
