# 牌桌场景模型

## 1. 场景目标

Halli Galli 的核心不是手牌管理，而是让所有人同时看清全部顶牌并快速触达中央铃。场景优先级从高到低为：

1. 所有当前顶牌同时可见；
2. 铃铛固定、醒目且可立即操作；
3. 当前翻牌者和每名玩家资格清楚；
4. 水果图例可核对，但默认不替玩家计算总数或宣布答案；
5. 动画、装饰和聊天不得遮挡上述区域。

机器可读定义见 `model/scene-catalog.json`；`assets/table-scene.svg` 是四人有效铃局面的静态信息架构原型。

## 2. 逻辑画布与坐标

宽屏基准为 1600 × 900 逻辑像素，场景区域使用 0-1 归一化矩形。渲染时按可用容器缩放，不假定页面全屏。

| 层级 | 内容 | 典型 z-index |
| --- | --- | ---: |
| 桌面层 | 纹理、席位轨道 | 0-10 |
| 牌堆层 | 抽牌堆、明牌顶牌、堆高 | 20-40 |
| 信息层 | 玩家名、资格、当前回合、四果合计 | 50-70 |
| 抢铃层 | 中央铃、按下反馈、锁定环 | 80-100 |
| 覆盖层 | 规则、网络警告、结果 | 120-180 |
| 系统层 | toast、屏幕阅读器 live region | 200 |

铃铛所在层永远高于牌面动画；除模态结果和明确暂停外，不允许其他元素拦截其指针事件。

## 3. 固定区域

| 区域 ID | 职责 |
| --- | --- |
| `table_stage` | 圆角桌面和整体安全区 |
| `bell_zone` | 中央铃与按下状态，所有人数共用固定锚点 |
| `fruit_legend` | 香蕉／草莓／青柠／李子的形状与名称图例；忠实模式不显示聚合总数 |
| `turn_banner` | 当前翻牌者、最早可翻时间和阶段提示 |
| `network_badge` | 本人 RTT 档位与连接状态，只作提醒 |
| `reaction_banner` | 正确、误按、被抢先、旧画面等短反馈 |
| `self_controls` | 本人翻牌按钮、键盘提示和禁用原因 |
| `event_strip` | 最近 3 条公开事件；不展开全部被覆盖牌 |
| `rules_drawer` | 快速规则与水果图例 |
| `result_overlay` | 终局卡牌统计、胜者、结束原因与再来一局 |
| `seat_0` … `seat_5` | 最多六个相对座位容器 |

每个席位内部固定有 `identity`、`draw_stack`、`top_discard`、`discard_count` 和 `status_chip` 子区。顶牌空时保留相同占位，避免桌面布局跳动。

## 4. 座位映射

玩家视角把本人固定映射为相对座位 0，其他人按顺时针排列；观众使用房间座次但保持同一几何模板。

### 4.1 宽屏布局

| 人数 | 相对位置 |
| ---: | --- |
| 2 | 本人下、对手上 |
| 3 | 本人下、对手左上／右上 |
| 4 | 本人下、对手左／上／右 |
| 5 | 本人下、对手左下／左上／右上／右下 |
| 6 | 本人下中、其余沿上半椭圆等距分布 |

每个席位的明牌朝向保持正立，不随桌边旋转，减少实时识别负担。抽牌和明牌之间至少留 12 px，使“背面堆”和“当前可见牌”不会混淆。

### 4.2 窄屏布局

320-759 px 采用“全员顶牌矩阵 + 固定中央铃”：

- 对手顶牌按最多 5 列缩小到 44 × 68 px，始终同时显示；
- 名称截断但座位号和资格图标保留；
- 本人席位在铃下方，顶牌尺寸略大；
- 四果图例使用 2 × 2 紧凑网格，不显示自动合计；
- 事件条折叠为单行，规则抽屉覆盖打开；
- 页面本身不横向滚动，也不使用轮播隐藏玩家。

375 px 以下若五列无法满足文字宽度，隐藏对手全名而保留“P2…P6”、顶牌数字和水果轮廓。

## 5. 席位状态

| 状态 | 视觉与文案 | 规则含义 |
| --- | --- | --- |
| `ready` | “可翻牌／可抢铃” | 有抽牌且仍在局 |
| `current_turn` | 双层描边 + “轮到翻牌” | `currentPlayerId` 指向该玩家 |
| `last_chance` | 琥珀标签 + “无牌·仍可抢铃” | 抽牌为 0，明牌仍在且有资格 |
| `eliminated` | 降低桌牌区饱和度 + “已退出” | 不可翻牌或按铃；遗留顶牌仍计数 |
| `ring_claimed` | 短暂脉冲 + “先按到” | 服务器确认该玩家赢得本次铃 |
| `wrong_bell` | 红色轮廓 + “误按·罚 N 张” | 普通罚牌或最终二人失利 |
| `disconnected` | 插头图标 + “重连中” | 不直接改变规则资格 |

所有状态同时有文字或图标，不以颜色作为唯一编码。

## 6. 核心场景

### 6.1 `waiting_room`

显示人数、两种终局档案、实时网络提示和规则速览。未开局不显示可操作铃，以免两人开局前误触直接结束。

### 6.2 `playing_self_turn`

本人抽牌堆与“翻牌”按钮获得主焦点；中央铃仍可按。若最短翻牌保护尚未结束，按钮显示明确倒计时而不是无解释禁用。

### 6.3 `playing_other_turn`

对方抽牌堆高亮，自己的翻牌按钮不可用；铃保持主快捷键。屏幕阅读器播报“轮到 P3 翻牌”，但不要提前播报隐藏牌。

### 6.4 `exact_five_visible`

牌面照常更新，内部计数不直接呈现，也不自动闪烁答案或播放独有提示，否则会替玩家完成观察。铃仅在有人实际提交后表现按下。

### 6.5 `bell_resolved_correct`

服务器确认后显示赢家、触发水果和收牌张数；各明牌堆用 220 ms 路径汇入赢家抽牌堆。减少动态模式只做赢家轮廓和数值跳变。

### 6.6 `bell_resolved_wrong`

普通阶段显示罚牌目标和张数；最终二人显示对手收走全部明牌。反馈完成前可以锁定翻牌与重复铃，但锁定时间只用于已完成的权威结算，不影响先前排序。

### 6.7 `last_chance_player`

无抽牌玩家的席位明确写“仍可抢铃”，不渲染翻牌按钮。若其明牌被收或其误按，过渡到退出状态。

### 6.8 `finished`

结果层列出每人的抽牌／明牌／总数、结束原因和赢家。`no-progress` 必须显示“数字安全裁决”，不能与正常最后铃混淆。

## 7. 交互契约

### 7.1 铃铛

- 指针／触摸：`pointerdown` 触发，避免等待 click；随后阻止同一指针的重复事件。
- 键盘：Space 触发，忽略 `event.repeat`；输入框／规则抽屉获得焦点时不劫持空格。
- 每名玩家、每个 `boardEpoch` 最多发送一个未完成请求。
- 本地只显示“已发送”；`正确／误按／被抢先` 等结果必须来自服务器。
- 触摸目标最小 64 × 64，周围 12 px 内不放危险按钮。

### 7.2 翻牌

- 点击本人抽牌堆、主按钮或按 Enter／F 均调用同一 `flip_card`。
- 只有 `actions.canFlip` 为真时启用。
- 卡面更新与 epoch 同帧提交；翻转动画不能遮住中央数字超过一帧。
- 动作失败时回到服务端快照，不保留乐观牌面。

### 7.3 规则与结果

规则抽屉不应自动打开；打开时它是模态层并暂停本地快捷键，但不暂停远端游戏。进入实时对局前明确提示这一点。结果层才真正阻止游戏动作。

## 8. 动效与声音

| cue | 建议时长 | reduced-motion |
| --- | ---: | --- |
| `card_flip` | 180 ms | 淡入 80 ms |
| `bell_press_local` | 70 ms | 轮廓瞬变 |
| `bell_confirmed` | 160 ms | 文字 + 轮廓 |
| `collect_piles` | 220 ms | 直接更新堆高 |
| `penalty_transfer` | 180 ms | 数字增减 |
| `player_eliminated` | 200 ms | 状态标签切换 |
| `final_duel_armed` | 260 ms | 静态横幅 |
| `result_enter` | 240 ms | 淡入 100 ms |

铃声、翻牌声和震动都可关闭；它们只能补充视觉与文字状态。声音在服务端确认后播放，避免本地误导。移动设备震动需遵循系统和用户设置。

## 9. 可访问性

- 顶牌 `aria-label` 示例：“白川，3 个香蕉，明牌堆共 7 张”。
- 铃按钮标签包含资格：“按铃，当前可用”或“按铃，不可用：你已退出”。
- 动态消息使用 `aria-live=polite`；本人铃结果可用 `assertive`，但连续翻牌不能刷屏。
- Space、Enter、F 的说明可在设置中查看；焦点环不被移除。
- 文字与背景普通内容对比度至少 4.5:1，关键大号数字至少 3:1。
- 水果用几何轮廓、文字和数量冗余编码；提供去色测试截图。
- `prefers-reduced-motion` 下禁用翻面旋转、飞牌和脉冲。
- 游戏本质依赖反应速度；“练习／宽限”模式若未来加入，必须标为非排位规则变化，不能宣称完全消除运动能力差异。

## 10. 场景数据与组件映射

| JSON 类型 | 前端组件 |
| --- | --- |
| `zones[]` | `GameView` CSS grid／absolute anchors |
| `seatLayouts[]` | `PlayerSeat` 相对位置 |
| `seatStates[]` | `PlayerSeat` 状态 token |
| `scenes[]` | 阶段到区域、焦点与动作映射 |
| `animationCues[]` | 事件序号到本地可取消动效 |
| `breakpoints` | container query 和最小卡牌尺寸 |
| `accessibility` | 快捷键、live region 和对比度测试输入 |

每个服务端事件有单调 `seq`。客户端只为尚未播放的序号执行一次动效；重连默认直接呈现当前状态，不重播整个收牌序列。

## 11. 原型图说明

`assets/table-scene.svg` 展示四人场景：阿梨的 2 香蕉与白川的 3 香蕉构成有效铃，青禾和赤岩显示其他水果；中央铃、四果合计、抽牌堆高、资格和当前玩家均可见。该图只表达信息架构，不复制官方桌布、包装或卡图。

## 12. 视觉验收

- 2-6 人在所有目标宽度下全部顶牌同时可见。
- 任何动效帧中铃目标不移动、不缩到 64 px 以下、不被遮挡。
- 玩家能在 72 px 卡高下分辨四种水果和 1-5 数量。
- 顶牌、堆高、抽牌堆和资格不会被误读为同一状态。
- 正确、误按、旧版本、被抢先四种反馈文字不同。
- 明牌被覆盖后旧牌不会继续出现在实时计数区。
- 键盘、触摸、鼠标和减少动态模式通过测试。
- 场景 SVG 可重建、无外链资源、无官方素材。
