# 场景与卡牌模型

## 1. 分层

模型分成三层：

1. `model/card-model.json` 定义可生成的卡牌几何、规则优先级、语义材质和读屏文案；
2. `model/generated-card-catalog.json` 固化 104 张实际牌记录，供检查和外部工具消费；
3. Vue/CSS 依据服务端卡牌视图渲染，绝不从颜色或图片反推牛头分。

`scripts/generate_models.py` 同时生成完整目录、`assets/card-model-sheet.svg` 和 `assets/table-scene-blueprint.svg`。生成物应提交，以便代码审查直接比较规则与视觉变化。

## 2. 卡牌几何

- 逻辑尺寸：68 × 96；圆角 9；安全内边距 6。
- 主数字区：视觉高度约占 52%，必须在 40px 卡宽下仍能识别三位数。
- 牛头分区：同时显示角形图标数量与“n 分”文本；颜色只是第二编码。
- 牌背：夜青色牛角格纹，所有玩家统一，避免通过细微差异识牌。
- 点击区：最少 44 × 44 CSS px；手牌窄屏允许容器内滚动。

## 3. 语义材质

| `tier` | 分值 | 语气 | 用途 |
| --- | ---: | --- | --- |
| `single` | 1 | 冷静青绿 | 普通安全牌 |
| `double` | 2 | 琥珀 | 尾数 5 |
| `triple` | 3 | 珊瑚 | 整十牌 |
| `quintuple` | 5 | 紫红 | 对子数 |
| `royal` | 7 | 强警示赤红 | 55 |

视觉不能把高分牌伪装成低分牌；`bullheads` 数字和图标总是来自服务端同一字段。

## 4. 场景目录

`model/scene-catalog.json` 规定七个场景。前端使用 `sceneId` 而非自行拼接阶段：

- `setup.table`：未开局牌桌；
- `turn.select`：本人暗选；
- `turn.waiting`：本人已锁定；
- `turn.resolve`：同时揭示和升序落位；
- `turn.choose-row`：低牌选行；
- `round.summary`：本轮新增分与总分；
- `game.finished`：最终排名。

每个场景都有明确进入条件、焦点区域、动作和退出条件。这样设计稿、测试与服务端投影可以共享同一组 ID。

## 5. 场景构图约束

四行是永远不变的空间锚点。动画可以把卡牌暂时放到揭示轨或飞行层，但稳定快照必须满足：

- 四行顺序不因分值排序而改变；
- 每行从左到右严格递增；
- 每行最多五张；
- 新行首留在原行位置；
- 玩家计分轨不随当前行动者重排；
- 本人手牌固定在底部，其他人手牌不画正面。

## 6. 原创概念图的角色

`images/table-concept.png` 只提供午夜青毡、黄铜、象牙纸和暖边光的气氛参考。其生成式示意牌不满足唯一牌号或五张上限，不能作为规则模型、测试基线或玩法截图。规则准确的静态参照是两张 SVG 模型板。
