# 《算途疾行》桥面场景模型

> 三跑道云桥、连续前进、2/3 路分叉、实体障碍与失败反馈 v4.0

## 1. 镜头

- 第三人称追逐镜头，略微俯视。
- 消失点位于画面水平中心约 30% 高度。
- 人物位于底部中心，题牌位于 24%–38% 高度。
- 所有跑道从人物附近向消失点收束，明确表达持续向前。

远景使用 `frontend/assets/runner-bridge-backdrop.png`，只提供峡谷、城市、日落和中央桥梁气氛；它位于独立镜头层中，会缓慢放大和纵向漂移。运行时跑道、题牌、障碍与近景速度参照均由 DOM/CSS 绘制。

## 2. 桥面

- 主桥使用石墨复合板和暖金属护栏。
- 三块实体桥板按不同题号切换轻微分叉角度，组成左、中、右三条跑道。
- 七枚稀疏路面碎石从消失点扩张到镜头下方，循环间隔随等级缩短，避免密集线条造成视觉噪声。
- 两侧各 4 个琥珀路标沿护栏从远到近移动并放大，提供明确的视差尺度。
- 题牌、断桥标记和障碍按单题时限从远端接近玩家；新题或重开时重新开始接近时间轴。
- 左右外缘始终有护栏；未开放路线使用实体破口和深色裂谷表现，玩家误入左右路线时会播放坠桥反馈。

## 3. 分叉

每题服务端从三个槽位中开放 2 条或 3 条：

```text
          消失点
    左道   中道   右道
      \     |     /
         跑者
```

- 开放跑道：完整桥板、玻璃题牌和动作键提示。
- 封闭跑道：实体桥板在路口处断裂，使用不规则崖口与深色裂谷表现，不再叠加斜纹或文字牌。
- 不绘制向天空或向地面的道路。
- 画面中的“2 路分叉 / 3 路分叉”雷达直接来自服务端 `branchCount`。

## 4. 障碍

只有中间跑道使用垂直障碍：

| 障碍 | 轮廓 | 动作 |
| --- | --- | --- |
| 低墙 | 一堵岩墙叠加三个凸起石块 | W / jump |
| 高墙 | 两立柱 + 厚墙体与琥珀警示条，下方留空 | S / slide |

障碍与题牌动作一一对应。同一中间跑道不会同时出现两种障碍。

## 5. 题牌

- 每条开放跑道只有一块题牌。
- 题牌保持正对屏幕，不随桥面透视扭曲，优先保证算式可读。
- 题牌包含键帽、箭头、动作名、等式和跑道名。
- 答对后正确题牌显示勾；错答时所选题牌显示叉。

## 6. 人物与前进感

- `RunnerModel` 位于桥面底部中心。
- 八个完整奔跑帧连续循环，腿、髋、肩和手臂的轮廓均会变化。
- 远景、实体桥板、路面碎石、双侧路标和角色步频组成远中近视差，并同时随等级加速。
- A/D 切换专用转弯姿势，人物横向移动，桥面和镜头向反方向转动。
- W 切换专用跳跃姿势并明显腾空收腿。
- S 切换专用低姿滑行动作并穿过横梁。
- 左右路线失败时裂谷扩大、镜头倾斜，人物播放坠桥姿态；中间动作失败时播放撞墙、冲击闪光和碎片。
- 失败动画结束后再显示结算卡，完整保留关键视觉反馈。

## 7. 宿主返回按钮

普通模式下插件根节点：

- 使用 `position: relative`；
- 保持在 `arcade-game-stage` 内；
- 高度为视口减去宿主房间头部；
- 不写入 `html` / `body` class；
- 不覆盖宿主 `RoomExitButton`。

因此“返回/放弃并退出”由宿主执行，可正确通知服务端并返回大厅。只有用户主动进入浏览器 Fullscreen API 时插件才固定占满屏幕。

## 8. 响应式

- 桌面：场景在左，控制台在右。
- 低高度横屏：压缩头部、题牌和角色尺寸，保持一屏。
- 手机竖屏：显示旋转横屏提示。
- 全屏：插件内部提供退出全屏按钮；退出后宿主返回按钮恢复可见。

## 9. 减弱动态

减弱动态时停止远景漂移、碎石、路标、题牌接近、失败粒子和循环步态，但保留静态三跑道、完整人物姿态、断桥、障碍、题牌、倒计时与结果标记。
