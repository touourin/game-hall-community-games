# 《算途疾行》玩家模型

> 角色外观、几何分层、动作锚点与无障碍规格 v1.0

## 1. 角色定位

玩家角色“逐光者”是一个中性、轻量、友好的跑者模型。角色负责传达速度、选择方向和失败原因，不承担题目或规则信息。

原创角色设计稿位于 `images/runner-character-concept.png`。设计稿用于统一轮廓、配色和动作语言；运行时采用 CSS 几何模型重建，以适配主题、屏幕尺寸和减弱动态效果。

## 2. 视觉构成

| 分层 | 形状 | 基础材质 | 动画职责 |
| --- | --- | --- | --- |
| 头部 | 圆角椭圆 + 短发轮廓 | 暖象牙/深石墨 | 跑动微沉、转向先导 |
| 躯干 | 收腰圆角梯形 | 深石墨夹克 | 呼吸、转向扭转 |
| 导航芯 | 胸前小型菱形 | 低饱和琥珀 | 答对与升级反馈 |
| 左/右臂 | 两段胶囊体 | 石墨 + 象牙护腕 | 与对侧腿反相摆动 |
| 左/右腿 | 两段胶囊体 | 深石墨 | 跑步步态与刹停 |
| 鞋 | 扁圆楔形 | 中性金属边 | 接触地面、转向蹬地 |
| 接触影 | 扁椭圆 | 半透明阴影 | 表达落脚与腾空 |

角色设计尺寸为逻辑高 `112`、宽 `58`。桌面舞台渲染高 `92–122 px`，手机渲染高 `72–96 px`，始终低于路口宽度的 22%。

## 3. 颜色与主题

- 主体材质使用 `metal.body`、`metal.side` 与 `copy.onStage`。
- 轮廓和关节使用 `metal.edge`，保证浅色主题下仍有边界。
- 胸前导航芯使用 `stage.glow`；只有服务端确认答对后才短暂切换到 `semantic.successGlow`。
- 失败状态同时使用姿态、图形标记和文字，不只把导航芯改成红色。

## 4. 动作锚点

角色根节点位于双脚中点，局部坐标如下：

```text
runner-root (0, 0)
├── shadow-anchor (0, -2)
├── pelvis (0, -25)
│   ├── left-leg-anchor  (-11, 0)
│   └── right-leg-anchor (11, 0)
├── torso (0, -57)
│   ├── left-arm-anchor  (-19, -14)
│   ├── right-arm-anchor (19, -14)
│   └── navigation-core  (0, -8)
└── head (0, -89)
```

所有肢体围绕锚点旋转；根节点只用于上下起伏、横向偏移和整体偏航。

## 5. 核心姿态

### `run-loop`

- 周期随等级从 `720 ms` 缩短到 `430 ms`。
- 双臂摆幅 `±24°`，双腿摆幅 `±28°`，左右相位相反。
- 根节点上下位移不超过 `3 px`，避免角色遮挡下方向题牌。

### `turn-left` / `turn-right`

- 预备 80 ms：头与肩先向目标方向偏转 `8°`。
- 压身 180 ms：躯干滚转 `±14°`，外侧臂展开，内侧腿蹬地。
- 通过 220 ms：根节点横移 `±18 px`，角色整体偏航 `±34°`。
- 回正 140 ms：进入下一段 `run-loop`。

### `turn-up`

- 角色短暂缩小 4% 并上移 `5 px`，表现向远处直行。
- 胸前导航芯向前产生一次收束光环。

### `turn-down`

- 采用半步回转而不是人物完全背向镜头：肩部偏航 `22°`、根节点下移 `8 px` 后回到中心。
- 场景进行较明显的纵向滚动来补足“向下”路线语义。

### `stumble`

- 错答时双臂张开、躯干前倾 `18°`、脚步错位，360 ms 后停止。
- 不出现坠落、受伤或暴力碰撞。

### `brake-timeout`

- 超时时双脚前撑、躯干后倾 `10°`，接触影横向拉长。
- 障碍在角色前方闭合，角色保持安全距离。

### `finish`

- 第 100 题答对后，角色做一次短冲刺并逐步减速，导航芯持续点亮。

## 6. 状态映射

```text
服务端 playing + 未提交      -> run-loop
本地已提交等待响应           -> commit lean
新快照 lastResult=correct    -> 对应 turn-* -> run-loop
新快照 levelUp=true          -> turn-* + level pulse
服务端 finished/wrong        -> stumble
服务端 finished/timeout      -> brake-timeout
服务端 finished/completed    -> finish
```

客户端提交期间可以锁住重复输入，但不能预判答对动画。转向方向来自服务端确认后的 `lastDirection`。

## 7. 无障碍与减弱动态

- 角色动画不包含必须读取的规则信息；关闭动画不影响答题。
- `prefers-reduced-motion: reduce` 时肢体固定在中性跑步姿态，转向改为 160 ms 的方向箭头淡入。
- 失败原因由 `role="status"` 文本同步播报。
- 角色模型设置 `aria-hidden="true"`；读屏只读取题目、方向、时间和结果。

## 8. 验收标准

1. 同一角色在奔跑、四向转弯、错答、超时和通关姿态中保持一致轮廓与配色。
2. 动画只在服务端确认后进入结果姿态。
3. 手机端角色不覆盖任何开放方向题牌。
4. 10 个速度等级的步频可辨认，但最高等级不产生刺眼抖动。
5. 减弱动态效果下没有无限循环动画。
