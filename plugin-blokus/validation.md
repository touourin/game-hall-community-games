# 四人方格插件验收

## 范围

本功能全部位于第三方仓库：`plugin-blokus/` 保存游戏、棋块目录、规则、图标和测试，`registry.json` 启用插件。不修改主 `game-hall` 的代码、SDK 或数据库结构，也不在主仓库提交子模块指针变更；本地只检出社区 PR 分支进行验证，无需配套主项目 PR。

验证宿主为上游 `game-hall` 的 `6256a33`，社区仓库基线为 `332bca1`。插件直接使用 API v1 的 `outcome` 类型，通过 `player_result()`、`player_score()` 和 `record_state()` 保存每局名次、+2 / +1 / 0 / −1 积分及结算快照。个人战绩文字和对局详情包含名次分；大厅排行榜保留既有胜负统计，不提供跨局累计积分榜。

规则测试独立枚举全部 21 种自由多格骨牌及 91 个不同方向，并用独立暴力搜索验证自然终局。覆盖四角开局、同色角接、禁止同色边接、越界重叠、伪造参数、回合重放、自动跳过、弃权、只读观战、重连及 0 / 负分结算。

续局针对「房主先手」「随机先手」两种设置、两组种子，分别连续检查五局：必须所有玩家准备，库存恢复，座位与颜色一致，每人轮换四个起始角。

`tests/test_records.py` 在插件目录内使用真实引擎、房间管理器、宿主持久化流程及独立 SQLite，验证有符号分数、战绩说明、胜负统计、重复保存、续局和游客对局排除。宿主内部模块只用于集成测试；插件生产代码仅从公开 `backend.app.games.plugin_api` 导入宿主类型。

## 本地联机验收

复用用户授权创建的恰好四个本地测试账号，通过真实 HTTP / Socket.IO 会话测试，不注入房间状态、不绕过认证。以下结果均在未修改的宿主上取得：

- 四客户端完成两局自然终局，均为 70 次合法落子；最终修订版再次通过。每局从四个不同角开始，每人获得 21 块、89 格。
- 检查拒绝三人开局、错误起始角、非当前玩家行动、同色边接、缺少角接、越界、重叠、重复棋块、旧回合和伪造参数；拒绝后棋盘不变。
- 每局后重新准备，验证座位与四个起始角一同轮换、21 块库存恢复；另测试弃权结算和保留已落棋块。
- 浏览器控制一名玩家，其余三名通过真实连接操作。验证选择棋块、旋转、翻转、非法预览禁用确认、查找落点及两轮共 8 步落子，然后通过弃权结束并核对四人排名。
- 浏览器刷新及测试客户端断线重连均保留棋盘、库存和回合；其他账号不能用别人的恢复令牌占用座位。
- 390px 手机宽度下无页面横向溢出；放大棋盘后容器宽 315px、内容宽 600px，仅棋盘内部滚动。1440px 桌面布局正常。
- 真实 API 与页面验证单局积分 **+2、+1、0、−1**、个人历史中的名次分和详情中的四人结算说明。宿主既有胜负统计保持不变，不展示累计名次积分。

此前依赖主项目扩展的累计积分榜验收不作为本版本结论。

本地测试账号、密码、会话、SQLite 文件、截图和运行日志不提交。测试使用本地 SQLite，未部署到远端，也未执行生产 MySQL / Redis 环境验收。

## 复验命令

在未修改的主项目中将社区子模块检出到本 PR 分支，然后在主项目根目录执行：

```sh
python -m pytest backend/tests
python scripts/test_community_games.py
npm --prefix frontend run test:run
npm --prefix frontend run build
```

前端既有时钟测试需使用 `Asia/Shanghai` 时区。Windows 后端运行使用本地兼容包装缩短过长的参数化测试名称，并仅跳过既有的 `test_katago_warm_up_uses_one_visit`：该测试创建的无扩展名 Unix 可执行文件无法被 Windows `shutil.which` 找到。包装不修改生产代码或测试断言。

主项目现有 `scripts/restart.py` 发布流程会将社区子模块更新到其正式 `origin/main` 后构建；社区插件合并和发布不依赖主仓库同步子模块基线。本次仅提交社区 PR，没有执行服务器部署。
