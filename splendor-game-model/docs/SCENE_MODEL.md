# 《璀璨宝石》场景与交互建模

## 1. 设计目标

场景要让玩家在一个视口中持续看见四类核心信息：三层市场、贵族、公共棋子供应和所有玩家的引擎。视觉可以有珠宝商会氛围，但规则信息必须比装饰更突出。

场景模型位于 `model/scene-catalog.json`，原创桌面线框位于 `assets/table-scene.svg`。模型描述逻辑区域和状态映射，不规定具体 Vue/CSS 实现。

## 2. 坐标与视角

- 桌面逻辑画布：`1600 × 1000` logical pixels；
- 坐标原点：左上角；JSON 中区域使用 0-1 归一化矩形；
- 当前观看者锚定底部中央，其他玩家按相对座位顺时针排列；
- 2/3/4 人共享同一舞台，只改变对手摘要数量；
- 观众使用中立视角，不显示任何玩家的私密抽屉；
- 页面根节点禁止横向滚动，卡牌行和玩家轨可以是局部滚动区。

## 3. 稳定区域

| Zone ID | 作用 | 常驻内容 | 交互 |
| --- | --- | --- | --- |
| `status_bar` | 回合与最终轮 | 当前玩家、轮数、阶段、剩余行动者 | 只读 |
| `opponent_rail` | 对手概览 | 分数、棋子、五色奖励、卡数、贵族、保留数 | 可展开 |
| `noble_row` | 公共贵族 | 3-5 张贵族和本人完成进度 | 详情/选择 |
| `tier_3_market` | 3 级市场 | 牌堆数量、4 个槽位 | 购买/保留 |
| `tier_2_market` | 2 级市场 | 牌堆数量、4 个槽位 | 购买/保留 |
| `tier_1_market` | 1 级市场 | 牌堆数量、4 个槽位 | 购买/保留 |
| `gem_supply` | 公共供应 | 五色宝石和黄金数量 | 选色 |
| `self_tableau` | 本人引擎 | 五色奖励列、威望、已购买卡数、贵族 | 展开 |
| `reserved_drawer` | 本人保留区 | 最多 3 张完整保留牌 | 购买 |
| `action_dock` | 当前行动 | 选色、确认、取消、行动原因 | 主要操作 |
| `payment_sheet` | 购买支付 | 费用、奖励、五色支付、黄金替代 | 模态确认 |
| `resolution_sheet` | 强制后处理 | 归还棋子、选择贵族、结果 | 模态确认 |
| `event_strip` | 公开历史 | 最近 3-5 个脱敏事件 | 可展开 |

市场三个等级保持固定纵向顺序：3 级在上、2 级居中、1 级在下。这样高等级与高威望在视觉上也更高，但每行都使用清晰“1/2/3 级”文字，避免纯位置依赖。

## 4. 桌面端布局

```text
┌────────────────────────────────────────────────────────────────────┐
│ 状态栏：轮到谁 · 第几轮 · 最终轮剩余玩家                         │
├────────────────────────────────────────────────────────────────────┤
│ 对手轨：P2 摘要             P3 摘要              P4 摘要           │
├──────────────────────────────────────────────┬─────────────────────┤
│ 贵族  [N] [N] [N] [N] [N]                   │ 公共供应            │
├──────────────────────────────────────────────┤ 白 蓝 绿 红 黑 金    │
│ 3级牌堆 [卡] [卡] [卡] [卡]                 │                     │
│ 2级牌堆 [卡] [卡] [卡] [卡]                 │ 最近事件            │
│ 1级牌堆 [卡] [卡] [卡] [卡]                 │                     │
├──────────────────────────────────────────────┴─────────────────────┤
│ 本人引擎：五色奖励列 / 贵族                 保留牌抽屉             │
├────────────────────────────────────────────────────────────────────┤
│ 固定行动 Dock：意图、选择计数、确认、取消、禁用原因               │
└────────────────────────────────────────────────────────────────────┘
```

桌面宽屏优先让 12 张市场牌同时完整可见。对手已购买的具体卡可以按色叠放，仅露出每张牌顶部的奖励和威望；点击颜色列再展开完整列表。

## 5. 相对座位

本人永远是 `relativeSeat = 0`。其余座位由绝对 turn order 相对映射：

| 人数 | 相对座位分布 |
| ---: | --- |
| 2 | 本人底部；唯一对手顶部中央 |
| 3 | 本人底部；下一家顶部右；再下一家顶部左 |
| 4 | 本人底部；下一家右上；对家顶部中；上一家左上 |

对手轨中的顺序同时显示顺时针箭头和“下一家／对家／上一家”文本。不能靠 DOM 左右位置判断谁下一行动。

## 6. 场景状态

| Scene ID | 进入条件 | 主焦点 | 允许提交 |
| --- | --- | --- | --- |
| `setup_table` | 尚未开局 | 组件与玩家席位 | 无 |
| `turn_idle` | `turn_action` 且未选择意图 | 市场、供应、行动 Dock | 打开任一主要行动 |
| `take_different_select` | 选择不同色行动 | 五色供应与已选槽 | `take_different` |
| `take_same_select` | 选择同色行动 | 供应中可取两枚的颜色 | `take_same` |
| `card_action_select` | 打开市场牌或本人保留牌 | 卡牌详情与费用 | 购买或公开保留 |
| `blind_reserve_select` | 打开牌堆菜单 | 三个等级牌背与剩余数 | `reserve_blind` |
| `payment_compose` | 准备购买 | 支付明细 sheet | 购买动作 |
| `return_tokens` | 服务端阶段为 `return_tokens` | 强制归还 sheet | `return_tokens` |
| `choose_noble` | 服务端阶段为 `choose_noble` | 合资格贵族 | `choose_noble` |
| `final_round` | 已触发终局但仍有玩家行动 | 状态栏倒计时 | 当前阶段合法动作 |
| `game_finished` | `finished` | 排名、同分过程、再来一局 | 宿主再来一局 |
| `spectator_table` | viewer 为观众 | 完整公开桌面 | 无 |

场景是表现状态，不是服务端新 phase。除 `return_tokens`、`choose_noble` 和 `finished` 外，选色、卡牌详情和支付编辑都可以是本地草稿；取消只清理草稿，不向服务端发动作。

## 7. 取棋子交互

### 7.1 不同色

点击“取不同色”后，供应按钮进入多选态：

- 服务端返回 `requiredDistinctCount`；通常为 3，供应短缺时为 2 或 1；
- 供应为 0 的颜色禁用并写明“供应已空”；
- 已选颜色显示序号 1/2/3、图标和文字，不只加亮边框；
- 达到要求数后确认按钮启用；再次点击可取消；
- 黄金按钮始终不进入候选。

### 7.2 同色

点击“取同色两枚”后，只高亮供应至少 4 的五色宝石。按钮显示动作前数量和动作后预览，例如“红宝石 4 → 2”。供应为 3 时写“至少需要 4 枚”，不能只置灰。

如果动作将让本人超过 10 枚，确认前显示提示，但允许提交。服务器随后进入强制归还阶段。

## 8. 卡牌详情与购买

桌面端点击卡牌打开就地侧栏，窄屏打开底部 sheet。详情包含：

- 卡牌等级、奖励色和威望；
- 原始五色费用；
- 本人五色永久奖励；
- 折扣后的实际费用；
- 本人棋子与最少黄金需求；
- “购买”和“保留”是否可用及原因。

不要在单击卡面时直接购买。卡牌可能值得保留，且购买需要允许精确选择黄金支付。

市场牌显示“购买／保留”；本人保留牌只显示“购买”；对手保留牌没有动作按钮。三个牌堆牌背提供“盲保留”入口并显示剩余张数。

## 9. 支付编辑器

支付 sheet 使用逐色表：

| 色 | 原价 | 奖励 | 实际需求 | 宝石支付 | 黄金替代 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 钻石 ◇ | 3 | 2 | 1 | 1 | 0 |
| 蓝宝石 ◆ | 2 | 0 | 2 | 1 | 1 |
| 缟玛瑙 ● | 2 | 1 | 1 | 1 | 0 |

默认分配尽量少用黄金。每行的减号可以把一枚同色宝石改为黄金，加号可以改回；总需求保持不变。确认区持续显示“支付 3 枚宝石 + 1 枚黄金 = 4”。

当支付不可能时不打开编辑器，卡牌详情写出缺口。当卡牌免费时显示“永久奖励已覆盖全部费用”，确认支付全 0。

## 10. 强制后处理

### 10.1 归还棋子

`return_tokens` sheet 不能关闭。顶部显示“当前 12 / 上限 10 / 必须归还 2”。六色棋子都可选择，包括刚拿到的棋子和原有黄金；选择总数达到 2 才可确认。

底层页面仍只读可见，不能通过浏览器返回键绕过。断线重连直接恢复 sheet 和已由服务端要求的数量；本地未提交选择可以丢失。

### 10.2 选择贵族

`choose_noble` 只展示服务端给出的合资格集合，每张显示将获得 3 分和当前奖励如何满足要求。选择是强制的，不提供“以后再说”。确认后播放一次拜访事件。

## 11. 玩家引擎

本人引擎按五色分列：顶部显示颜色、奖励总数和该列威望，下面叠放已购买卡。默认只露出每张顶部 28%，保证奖励与威望可见；展开后展示完整获得顺序。

对手摘要至少显示：

- 姓名、当前行动标记和首位玩家标记；
- 总威望；
- 六色棋子数量；
- 五色永久奖励；
- 已购买发展卡总数；
- 贵族列表；
- 保留牌槽，公开来源显示卡面，盲抽显示等级牌背。

这些都是决策信息，不能为“简洁”默认隐藏到多个点击之后。手机端可以横向滚动对手轨，但当前行动者始终在可见起点。

## 12. 最终轮与结算

终局触发后状态栏切换为琥珀色，明确显示：

```text
最终轮 · 青岚已达到 15 分 · 尚可行动：赤羽、墨石
```

结算页分三列展示每位玩家：发展卡威望、贵族威望、总威望、已购买发展卡数。并列时逐步展示比较：

```text
青岚与墨石同为 16 分
青岚购买 12 张，墨石购买 11 张
墨石以较少发展卡获胜
```

若分数与卡数都相同，明确写“共同获胜”，不要随机选一个头像作为主赢家。

## 13. 响应式策略

### ≥ 1280 px

使用完整桌面布局，市场 4 列、三行同时可见；右侧供应固定；本人引擎与保留区并排。卡牌宽约 132-156px。

### 900-1279 px

供应压缩为两行六格，移到贵族下方；市场仍保持每级 4 列；对手轨局部横向滚动。支付与详情用右侧 sheet。

### 600-899 px

舞台纵向排列：状态栏 → 对手轨 → 贵族 → 供应 → 3/2/1 级市场 → 本人引擎 → 保留区。每个市场行自身横向滚动，并提供“第 1/4 张”位置提示；页面本身不横滚。

### ≤ 599 px

市场卡使用 118-132px 固定宽度，不再等比缩小。贵族、供应与玩家摘要使用横向滚动条；行动 Dock 固定底部。详情、支付和强制步骤用接近全屏的底部 sheet。

### ≤ 390 px

减少装饰和卡面插画高度，但保留威望、奖励、全部费用、等级和动作原因。顶部状态栏可换行，不截断玩家名与最终轮信息。最小点击目标保持 44×44 CSS px。

## 14. 动效事件

| Cue ID | 事件 | 建议时长 | 减少动态效果 |
| --- | --- | ---: | --- |
| `pieces_taken` | 供应到玩家摘要 | 380ms | 数量淡变 |
| `pieces_returned` | 玩家到供应 | 320ms | 数量淡变 |
| `card_reserved_public` | 市场到保留槽 | 420ms | 轮廓闪烁 |
| `card_reserved_blind` | 牌堆牌背到保留槽 | 360ms | 牌背淡入 |
| `card_purchased` | 市场/保留到引擎色列 | 520ms | 目标列高亮 |
| `market_refilled` | 牌堆到空槽 | 280ms | 新卡淡入 |
| `noble_acquired` | 贵族到玩家摘要 | 560ms | 分数与贵族轮廓高亮 |
| `final_round_triggered` | 状态栏切换 | 420ms | 即时换色加文字 |
| `game_finished` | 排名展开 | 650ms | 直接显示完整排名 |

每个 cue 携带 `eventId` 和 `revision`。新快照到达时可以跳过尚未播放的非关键动画，不能延迟可操作状态。禁止用金币爆炸、屏幕抖动或大面积粒子遮住市场费用。

## 15. 主题与材质

建议中性珠宝商会主题：

```json
{
  "table": "#173B3A",
  "tableEdge": "#6A5138",
  "paper": "#F4F0E7",
  "ink": "#20292D",
  "brass": "#B78A3F",
  "focus": "#E8BD62",
  "danger": "#A8524B",
  "hidden": "#4D5961"
}
```

深浅主题保持卡牌几何、颜色符号、区域位置和信息层级一致，只切换桌面、纸张、边缘和阴影。背景装饰透明度低于 8%，不能与费用图标竞争。

## 16. 无障碍

- 所有颜色同时有中文名、符号和纹样；
- 当前玩家使用文字“轮到你”和边框，不只用绿色；
- 键盘顺序按贵族 → 3/2/1 级市场 → 供应 → 本人引擎 → 保留区 → Dock；
- 方向键在同一市场行移动，Home/End 到首尾，Enter 打开详情；
- sheet 打开时焦点圈入，关闭后回到触发卡或所在等级标题；
- 公共行动由礼貌级 `aria-live` 播报，强制归还与贵族选择用 assertive；
- 屏幕阅读器不播报任何非本人盲保留身份；
- 正文与背景对比至少 4.5:1，大号分数至少 3:1；
- 200% 缩放时仍能完成购买与归还，不依赖悬停；
- 尊重 `prefers-reduced-motion`，所有信息变化都有非动画文本结果。

## 17. 原型与验收

- 2、3、4 人都能从同一安全视图稳定映射到相对座位；
- 12 张市场牌、最多 5 张贵族和六色供应在 1280px 宽同时可读；
- 390px 宽无页面级横向滚动，局部卡牌行有明确滚动边界；
- 四种主要行动仅用键盘可完成；
- 黄金主动替代、归还 2 枚和多贵族选择都能看到精确数字；
- 对手与观众只看到盲保留牌背和等级；
- 最终轮清楚显示尚未行动者，结算可解释同分过程；
- SVG 原型不含官方 Logo、插画、肖像、纹样或扫描内容；
- 深浅主题、色觉缺陷模拟、减少动态效果和高缩放检查通过。
